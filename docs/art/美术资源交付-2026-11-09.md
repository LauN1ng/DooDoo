## 二、为什么卡面拆成「设计稿」和「底图」两套

用户原话是「把新画的卡片资源替换掉」。直接把 `brands/cards/*.svg`（18 张设计稿）贴进 App 会踩两个坑：

1. **文字会重影**：设计稿里有 `<text>`（品牌名 / 尾号 / 卡组织 / 类型标签）。这些是账户的可编辑数据，改名后图不会变，SwiftUI 再画一遍就是两层字。
2. **账户对不上**：设计稿是按 `brands.json` 的 13 个账户 + 5 张样卡各出一张，而真实账户由用户新建（SeedService 17 个，还能再加）。用户新建一个「招行第二张卡」时没有对应图。

所以拆成：

- `brands/cards/*.svg` —— 18 张**设计稿**，含文字，只用于 `index.html` 预览与验收截图，**不进包**。
- `brands/faces/*.svg` —— 63 张**底图**（21 品牌 × 3 variant），剥掉全部 `<text>` 与 `<clipPath>`，只留渐变 / 光影 / 芯片 / 行徽，**进包**。

底图与账户无关，只与「品牌 + 色阶」有关；文字由 SwiftUI 按 `Account` 实时画。这样改名、改尾号、新建账户都能正确显示。

去 `clipPath` 的另一个原因：圆角统一交给 SwiftUI 的 `clipShape`。图里再裁一次，在非等比缩放时会露出双层圆角。

## 三、63 张底图怎么来

`assets/_build/gen-card-faces.js`（新增）：

- 输入：`brands.json` 的 21 个品牌 + `logos/logo-<id>.svg`（生成时内联，文件自包含）。
- 规则与 `gen-brand-cards.js` **完全一致**：实体卡芯片左上 + 行徽右上；虚拟卡无芯片、行徽放大到左上；`variant` 0 原色 / 1 压暗 14% / 2 提亮 16%。
- 输出：296×186 SVG，无文字、无圆角裁切。

`assets/_build/sync-app-assets.js`（新增）负责落包，幂等：每次清空自己管的三组目录再重建，品牌改名不会留孤儿 imageset。

命名：`card-cmb-v0.svg` → `CardCmbV0`（`.imageset`），Swift 侧由 `BrandStyle.cardAsset(variant:)` 拼，两边规则必须一致。

**为什么色阶要 63 张而不是运行时算**：`variant` 是色相偏移（压暗后色相略偏），SwiftUI 的 `.brightness()` 只能整体加减明度，做不出同色系压暗的手感。之前 `variant` 字段存了但没生效，就是因为在运行时算不出来。

## 四、纹理与评分图标

| 组 | 资源 | 规格 | 用法 |
|---|---|---|---|
| `Texture/` | `TexMatte` / `TexMetal` / `TexGrain` | 1x 单倍，灰度、均值 128 | 运行时 `resizable(resizingMode: .tile)` + `blendMode(.overlay)`；matte/metal 0.40–0.46，grain 0.06 |
| `Grade/` | `GradeHang` / `GradePiao` / `GradeLa` / `GradeNpc` | 40pt：@2x 80、@3x 120 | 记一笔评分行显示 18×18 |

**纹理不给 @2x/@3x**：tile 模式下不同倍率的 tile 边长不一致，接缝会变粗。单倍图由系统按屏幕缩放，接缝连续。

**纹理必须 `compositingGroup()`**：不加这层，`overlay` 会和卡外的页面背景混色，纹理整体发灰。

评分图标的 18pt 显示尺寸是试出来的：素材是 40pt 规格，缩到 18pt 时内凹字心的细节已不可辨，但四档色块（红 / 蓝 / 紫 / 灰）在小尺寸下辨识度仍然够——这本来就是「方块 + 一个字」的设计意图。

版式为什么改：新底图把芯片放在左上、行徽放右上，原卡面把标题放在左上会与芯片重叠。所以文字整体下移到卡底——这与设计稿 `cards/*.svg` 的排布一致（左下品牌名、右下尾号）。

字号没有跟着底图等比缩：底图是 296×186，等比缩到 132 宽时品牌名只有 7.6pt，中文读不了。四档字号沿用 M2b 的那套（12.5 / 13.5 / 13 / 10.5）。

本轮新增三项校验（都在 `verify-assets.js`）：

1. **底图必须无 `<text>` / 无 `clipPath`** —— 残留就是重影或双圆角，肉眼在小卡上不一定看得出来。
2. **Asset Catalog 完整性** —— 每个 imageset 的 `Contents.json` 与其中引用的图必须都存在；三组数量分别为 63 / 3 / 4。
3. **`BrandPalette.swift` ↔ `brands.json` 一致** —— 逐品牌比对 `c1` / `c2` / `ink` / `chip` / `logo`。色值漂移是最难肉眼发现的一类 bug，之前 16 个品牌全是近似色就是这么积累下来的。

版式对照稿：`design/current/card-face-v2.html`（四档尺寸、21 品牌墙、variant 三色阶、评分行，全部 1:1 像素排版）。

## 七、遗留与风险

1. **SVG 进 Asset Catalog 已过编译，真机渲染未复看**：`4d25f55` 的 CI run `42648536927` 全绿（build + 48 个 `@Test` + IPA 打包），说明 `actool` 能正常处理这 63 张 SVG、`cardAsset()` 拼出的资源名与目录一一对应。但「编译通过」不等于「渲染正确」——底图是否正常显示、纹理强度是否合适，仍需真机确认。若底图空白，回退方案是把 63 张导成 @2x/@3x PNG。
2. **底图比例 1.586 与卡片比例 1.5–1.61 不相等**：用 `aspectRatio(.fill)` 裁切，四档尺寸下裁掉 0–2pt 边缘，芯片不会变形。
3. **`App.xcassets` 体积**：63 张 SVG 共约 800 KB（行徽 path 是大头），比位图方案小一个量级；但如果 Xcode 在编译期把矢量光栅化，实际会更小。
4. **行徽是注册商标**：本地自用无碍，上架仍需换「品牌色块 + 银行名简称」（`brands.json` 的 `short` 字段已备好）。
5. **`assets/` 不入库**（仓库白名单只放行 `app/` 与 `.github/`）：生成脚本与 `brands.json` 留在本地工作区，仓库里只有落包产物。换机器时需整体拷贝 `assets/`。
