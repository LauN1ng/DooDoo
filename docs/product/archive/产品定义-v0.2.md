## 一、一句话定位

> **一个只给自己用的账本：首页就是流水和记一笔，账户余额和真实对得上，负债什么时候能还完一眼能看到，界面好看。**

不做什么：不做社交、不做理财推荐、不做多端协作、不做记账教学、不做预算打卡社区、**v1 不做游戏化**。

---

## 二、三个痛点 → 三个产品承诺

| 痛点 | 产品承诺 | 衡量指标 |
|---|---|---|
| 账户余额必须和真实账户对得上 | 余额由流水推导，且能快速发现漏记 | 对账后差额 = 0 |
| 信用账户能看清何时结清 | 按实际还款额逐月推演，给出结清月份 | 能回答「这个月还完还剩多少」「照这样什么时候还完」 |
| 界面好看 | 打开不难受，看着舒服 | 自己愿意天天用（不是留存率） |

> **v0.2 修正**：原 v0.1 把「可玩性」写进核心承诺，现降级。好看是 v1 的要求，好玩是 v2 的模块。

## 三、痛点一的解法：三道防线（业界共识 + 本项目采纳）

**核心洞察**：市面上没有任何 App 靠"用户自律"做到"余额对得上"。真实答案都是这一套。但**三道防线不必都在 v1 落地**，见第六节优先级。

### 防线 1 · 账单导入
- 微信：微信支付 → 我 → 服务 → 钱包 → 账单 → 右上角 ··· → 常见问题 → 下载账单 → 用于个人对账
  - 接收方式二选一：**微信支付公众号下发（无需解压码）** 或 邮箱（需解压码）
  - 公众号通道：文件 7 天内有效；邮箱通道：长期有效
  - 格式：较新为 `.xlsx`（另有 `.csv`），UTF-8 编码
  - 单次最长可导出一年；下发需 24 小时内
- 支付宝：我的 → 账单 → 右上角 ··· → 开具交易流水证明 → 用于个人对账
  - 邮箱收到加密 ZIP，解压码走支付宝通知
  - 内含 CSV，**GBK 编码**（Mac / 英文系统直接双击会乱码，必须显式指定编码解码）
  - 可能按年份拆成多个文件
- 银行：CSV 导出（各行格式不同，需映射）

### 防线 2 · 待确认队列
导入后每笔标为「待确认」，用户逐笔核对：收付账户、金额、类型、分类。确认后才计入余额。
- 首次导入全部待确认；之后仅"识别明确的普通交易"可自动确认
- 京东 / 美团全部先待确认（易与微信/支付宝重复）
- 重复或错误记录 → **作废**（原始依据与操作记录保留可追溯）

### 防线 3 · 余额对账快照
用户从银行 App 看真实余额 → 手动输入 → 与推算值比对。
- **对账只记录时间戳，不修改余额、不修改流水**（aboka-ledger 的关键设计，务必照抄这个原则）
- 差异 = 漏记线索 → 反查待确认队列
- 不提供"直接改余额"按钮
- **v1 必须做**，因为这是「知道我有多少钱」的最小闭环

### 记录类型（六类，与 aboka-ledger 对齐）
`收入 / 支出 / 退款 / 转入 / 转出 / 不计收支`
- 退款必须关联原消费
- 自己账户间转账必须记录两端账户
- 账户期初余额是**一次性固定起点**，不是每次对账都改

## 四、痛点二的解法：结清推演

### 主口径 · 现金流推演（v0.2 定案）

```
下月欠款 = 本月欠款 × (1 + 月利率) + 本月新增消费 − 本月实际还款额
```

- 用户为每个负债账户填三个数：**当前欠款 / 年化利率 / 每月实际还款额**
- 逐月模拟到欠款 ≤ 0，输出结清年月
- 同时输出：本月还完剩余可支配 = 月收入 − 本月应还合计 − 本月固定支出

### 计划口径（v2，用于分期类账户）

| 要素 | 说明 |
|---|---|
| 分期类型 | 消费分期 / 还款分期 / 房贷分期 |
| 还款方式 | 等额本息 / 等额本金 / 先息后本 / 已知月供 |
| 服务费 | 按总额或费率；收取方式：按月均摊 / 首期收 / 立即收 / 服务费分期且到期收本金 |
| 余数处理 | 金额除不尽时：余数计入首期 / 末期 / 均摊至各期 |
| 首期差异 | 支持（`firstPeriodAmount`） |
| **末期差异** | **尚未建模**——涉及金额的实现变更前必须查官方规则并用真实账单验证 |

### 账户分层
- 资产账户（余额为正）：现金 / 银行卡 / 微信 / 支付宝 / 投资理财
- 负债账户（余额为负）：信用卡 / 花呗·白条 / 房贷·网贷 / 亲友借款
- 净资产 = 总资产 − 总负债（总资产不含负债账户）
- 信用卡正余额 = 溢缴款，不计入总负债

## 五、后置模块池（v1 不做，留位）

原来这里是「可玩性候选」，v0.2 起统一移出 v1 范围。设计时只需保证不被架构挡住。

| 形态 | 做什么 | 备注 |
|---|---|---|
| A 记账反馈 | 金额跳动 / 成功屏表情 | 成本低，最可能第一个加 |
| B 连续打卡 | 连续记账天数 → 徽章 | 成本低 |
| C 账户卡片收集 | 账户卡片解锁 | 与品牌素材耦合 |
| D 预算挑战 | 本月预算挑战 | 差异化低 |
| E 年度心情图 | 一年心情做成一张图 | 记忆点强 |

## 八、已知风险

1. **末期差异建模未解决** —— 分期每期金额涉及金额的实现变更前须查官方规则 + 真实账单验证
2. **账单导入是纯本地解析** —— 支付宝 GBK 编码、微信/支付宝表头各版本不同，需写健壮的解析器 + 单测（已延后到 v1.5，风险释放）
3. **支付宝 CSV 可能按年拆文件**，微信有 xlsx/csv 两种历史格式
4. **新建工程会丢弃 iOwn 已验证的 CI 配置**，需从 iOwn 复制 `codemagic.yaml` / workflow 后重新适配路径
5. **花呗/信用账户图标目前为代码绘制**，目标是替换为真实品牌图标库
6. **手动记账必然漂移** —— 靠防线 3 的对账快照兜底，不指望用户自律
