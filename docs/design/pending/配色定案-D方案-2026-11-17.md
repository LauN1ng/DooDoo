## 一、一句话定案

> **界面里只剩三种彩色来源：Fluent3D emoji、自绘卡面、折线（红绿）；其余全是墨、纸、边、影。**
> 「主题色」这个概念取消 —— 没有第五种色相，也就没有"主题色会不会跟数据色打架"这件事。

## 三、按钮四态（D 方案的完整语言）

| 态 | 底 | 边 | 字 | 影 |
|---|---|---|---|---|
| **主**（记一笔「保存」） | `#FFFFFF` | **1.5pt `#C9C0AE`** | 墨 700 | `0 3 9 -5 rgba(29,28,26,.5)` |
| **次**（编辑 / 还款） | `#FFFFFF` | 0.5–1pt `#D6CFC0` | 墨 600 | 无 或 `0 2 5 -3` |
| **危险**（删除） | 透明 | 无 | 红 `#A8332B` | 无 |
| **禁用** | 白 | 同次级 | `#9A9AA2` | 无，opacity .45 |

**统一规则：所有按钮都是白底 + 描边 + 墨字，不填任何色。** 主次只靠**边粗细/深浅**与**字重**区分（1.5pt/700 vs 0.5–1pt/600）。选中态沿用 `#E9E4D9`（pill）/ `#F0EDE6`（槽）。

> **必看的一处冲突**：记一笔里「保存」按钮与「备注」行都是白底 + 边，天然同构。原型已用「1.5pt 边 + 字重 700 + 影」把按钮拉开，**这条必须真机确认**——若仍读不出主次，备选是给保存按钮加 `#EDE9E1` 浅纸底（即回到 D′ 分工）。

## 四、描边 vs 浅纸：不是二选一，是分工

实测（暖白页底 / 白卡）：

| 做法 | 在暖白页底 | 在白卡内 | 读感 |
|---|---|---|---|
| **描边** 白底 + 1pt `#D6CFC0` + 影 | 边 **1.42** | 边 **1.55** | 凸起的实体，像能按 |
| **浅纸** `#EDE9E1` 无边框 | **1.11** | **1.21** | 平贴的一块，像填充区域 |

大面积色差 1.11 其实看得见，但**它不读作按钮**——在底栏还容易被当成一条分隔带。

**11-18 终版决定：全部按钮都用描边白底，不用浅纸。** 取舍是少一条规则、全局更统一；代价是详情页那个 34pt 小按钮偏弱一点，靠边和影硬撑。

## 五、这一轮被推翻的东西（请核对有无出入）

| 被推翻的 | 原因 | 换成 |
|---|---|---|
| 品牌色六版（松绿 / 靛蓝 / 深青 / 绯 / 墨+点 / 现状亮绿） | 全在"给主题色找位置"，而主题色本身是多余的 | D：取消主题色 |
| 「统一色系」U1（支出金额也红） | 一屏 10 处红，把逾期淹掉 | R2：单笔金额保持墨 |
| 「统一色系」U2（红绿主体 + 涨跌去色） | **数据层红绿保留；「涨跌去色」被 11-18 用户纠正推翻** | 涨跌保留红绿 |
| 纸与光（薄荷洗底） | 用户只是觉得浅色好看，不是选定薄荷 | D：无洗底 |
| 蓝主题 `#2C6BCB` / 六组蓝 | 用户澄清"只是觉得蓝浅好看"，没肯定蓝 | D：无蓝 |
| 八支浅色 wash（雾蓝…燕麦） | D 不需要 wash | 全部留档作参考 |
| 雾灰版 `#EDEAE4` | 与现有槽同层（ΔL 1.0）、按钮读成禁用 | 未采用 |
| **「主按钮用墨」** | 墨 L\*1.2 是全屏最重的，与"轻快"相反 | D 描边 |
| 双版切换 + 工作量评估（1 人日） | D 让"主题"消失，阶段 1 整段作废 | 估时降到 **2–3 h** |

**保留下来的早期决定**：
- 支出合计红 `#A8332B`、收入绿 `#1F7A52`（11-17 早"三层身份"那轮）
- **逾期另给一支亮红 `#D03A2E`**（11-18 定），与数据红分开
- 涨跌百分比**保留红绿**（11-18 用户纠正：它本身是一处颜色来源）
- 折线统一：我有绿**实线** / 我欠红**实线**，详情按账户类型；黑线与蓝橙退场
- 记一笔金额 `0.00` 从 46pt 收到 **34pt**（诊断"全 App 最大字是未输入的空金额"）
- 底 `#F7F5F1`、卡白、卡内距 20、详情卡面 240×151 —— 一律不动
