## 二、“只有一根折线”的根因

**是真 bug，而且是设计层面留下的。**

`TrendGeometry.positions` 原本**对每条序列各自按自身 min/max 归一化**，源码注释里还写着
「资产页的『我有 / 我欠』两条线不共用纵轴」——那是我上一轮定的。

后果：5,968.84 与 7,681.86 量级不同，但各自被拉满高，两条都变成「贴底 → 末端翘起」，
形状几乎一致 → **完全重叠** → 后画的红色盖住先画的绿色 → 真机只剩一根红线。

修法：`positions(...)` 新增 `domain: ClosedRange<CGFloat>?` 参数，`NetWorthCard` 传入
两组值合并后的 min/max，两条线共用同一纵轴。单条曲线（详情页）仍传 `nil`，行为不变。

## 三、按钮材质：为什么是「微凸纸片」

用户「按钮材质不对」。上一版是 **白底 + 1.5pt 实色描边 + 单层影**。

判断：问题不在边粗细，而在**描边的语义**——描边表达的是「边界」，不是「可按」。
在白卡里，白底 + 浅边 + 微影会被读成输入框或分隔区；边加深只会更像「框」。

在取消全部颜色（D 方案）的前提下，实体感只能靠「**光从上方来**」。新材质三层，全不带颜色：

| 层 | 做法 | 作用 |
|---|---|---|
| 渐变边 | 顶 `#FFFFFF` → 底 `#D6CFC0`，1.2pt | 纸的厚度被光打亮 |
| 贴地影 | `ink 6% / r1.5 / y1` | 定义轮廓贴在哪 |
| 环境影 | `ink 11% / r12 / y6` | 定义它浮起多高 |

落地为 `Views/Components/PaperButton.swift`：

- `PaperButtonBackground(shape:strong:)` + `.paperButton(cornerRadius:strong:)` —— 主按钮
- `PaperInsetBackground(shape:)` + `.paperInsetButton(cornerRadius:)` —— **卡内部**的行内按钮

**为什么卡内不用同一个材质**：卡内既不能用影（会变成「纸上又贴一张纸」），
也不能用描边（会被读成分隔线），只能用一块比白卡深一档的暖纸（`paperInset #EDE9E1`，与白卡 L\* 差 7.2）。

应用点：记一笔保存、存量分期保存、详情页还款（`strong: false`）、首页记一笔入口。

## 四、P8 撤回：信用折线的「贴底 + 尖峰」不是 bug

我上一轮把它判成「折线在说假话」，**判错了**。

`12` 招商详情 1 年区间：曲线从 y=1789 一条水平线，最右端升到 y=1523。
这**正是真实数据的形状**——账户 11/17 才建账，前面 11 个月欠款为 0，最后一天一笔 500。
渲染没错，是**数据量少**。

所以本轮**不改**，也不再压缩高度：改动只会让「两根不同账户类型的图长得不一样」，
反而制造新的不一致。真正缺的是「数据不足」这条产品状态（点数太少时显示什么），
那属于产品决定，不是渲染修复 —— 留待与用户确认。
