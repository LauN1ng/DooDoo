## 一、结论先行

用户给的 9 条里，**6 条是"黑块/重复/不统一"这类零歧义缺陷**，这轮直接改掉了；**3 条是交互级重构**（自绘键盘、卡面放大替代 sheet、详情页顶部重排），需要单独一批，方案见第四节。

> **12% 主色浅底 + 1.5pt 主色描边 + 图标 1.06 放大**，不用实底、不用黑。

## 三、这轮定下的 token

> ⚠️ **本节已被第七节降级为「过程记录，不作依据」**：11-16 中午用户真机看完说「记一笔重点色还是不对」「灰白首页看着更不对了」。下面的色值与对比度数值本身没错（都可复核），但**这套搭配不是定案**，下一轮要重做关系，见 7.1。

### 3.1 灰阶（完全中性，R=G=B）

| token | 值 | 用在哪 | 实测 |
|---|---|---|---|
| `page` | `#F6F6F6` | 页面底、页头、状态栏 | vs 白卡色差 **7.8%** |
| `card` | `#FFFFFF` | 卡面 | — |
| `slot` | `#F0F0F2` | 图标槽、选中块、未选中分类 | vs 白卡色差 **12.7%**（规格下限 5%） |
| `tabBed` | `#E9E9E9` | 顶部 tab 槽 | vs page 色差 **11.6%** |
| `line` | `#E8E8E8` | 分隔线 | vs 白卡 19.3% |
| `ink` | `#1D1D1F` | 标题、金额 | 白卡 **16.83:1** |
| `ink2` | `#5F5F66` | 次级文字 | 白卡 **6.33:1** |
| `sub` | `#6E6E76` | 说明文字 | 白卡 **5.05:1** / 页底 4.68:1 |
| `faint` | `#9A9AA2` | 纯装饰，不承载信息 | 白卡 2.79:1（刻意不用它放正文） |

旧值对照：`page #F7F5F1`（暖白）、`sub #A8A39A`（白卡只有 **2.51:1**，不达标）、`line #EFECE5`、`tabBed #EBE7E0`。

### 3.2 主色

| 用途 | 值 | 理由 |
|---|---|---|
| 描边 / 图标 / 图形 | `#3ABF58`（品牌绿） | 亮色只做图形，不做白字底（白字仅 2.39:1） |
| 实底按钮 / 胶囊（白字） | `#1B8230` = `accentFill` | 白字 **4.90:1**；规格绿 `#2FB344` 只有 2.74:1 |
| 选中态浅底 | 主色 12%（`accentWash`） | 与描边、放大共同表达"选中" |

`AccentStyle` 默认从 `ink` 改为 `green`，并加**一次性迁移**（`SeedService.migrateAccentIfNeeded`，`UserDefaults` 幂等标记）：只有库里存的是旧默认 `"ink"` 时才改写，用户以后主动选回「墨」不会再被改。

## 四、下一批的三个方案

### 4.1 自绘数字键盘（第 5 条）· 2026-11-16 已落地

**落地形态**（与下面原方案的差异已标注）：

- 结构：3 列 × 4 行 —— 1–9 三行，第四行 `.` `0` `⌫`。系统键盘那排 ABC / 地球键的位置直接省掉。
- 尺寸：键高 **52**、间距 **6**、圆角 **12**；整块 `4×52 + 3×6 = 226`，加内距 16 + 安全区。
- 材质：数字键 `Palette.card` 白卡 + 4% 投影；删除键 `Palette.slot`；按下态 `accentWash` + `0.97` 缩放，120ms。
- 字号：24pt `.medium` + `monospacedDigit`，与金额同族。
- 行为：**按下即删，长按 0.35s 后每 70ms 连删**；不提供「完成」，主按钮（高 54）就在键盘正上方。
- 位置：`.safeAreaInset(edge:.bottom)` 挂在页脚**外层** → 视觉顺序「页面 / 页脚主按钮 / 键盘」，整块底色 `Palette.page` + 0.5pt `Palette.line` 上边线。
- 落点：`Views/Components/NumberPad.swift`，含 `NumberValueText`（只读显示 + 呼吸光标）与 `PadKeyStyle`。
- 输入框：**不再是 `TextField`**，改为 `NumberValueText` + 整行点击，当前字段由视图自己的 `activeField` 记录（不走 `@FocusState`）。原因：只要还是 `TextField`，点一下系统键盘就会弹出来和自绘键盘叠在一起。
- 输入规则收在组件里一份：前导 0 不堆叠、整数位 ≤ 7、小数位 ≤ 2；已带两位零的联动值（`120.00`）敲数字时先去掉凑数的零。

**两处与原方案不同（都是实现时才发现的）**：

1. **整数位字段关掉小数点**（剩余期数 / 总共几期）——原来打算所有字段同一块键盘，实际那两格填不出小数，留一个按了没反应的键等于骗人。现在那一格留空，网格不变、手指记忆不废。
2. **备注与分期「名称」仍是系统键盘**——它们是文本不是数，用不了数字键盘。做法是它们聚焦时自绘键盘整体收起（`!noteFocused` / `!nameFocused` 才挂），两块键盘永不同屏。

**已知代价**：键盘 + 页脚合计约 322pt（38% 屏高），记一笔的分类网格与评分需要向下滚一屏才看全。这是「键盘常驻、主按钮永远可点」的必然代价；如果真机觉得挤，优先动键高（52 → 48，省 16pt）与键盘上下内距，**不动**主按钮与字段顺序。

### 4.2 卡面放大替代 sheet（第 8 条）

- 触发：`GroupOverlay` 里点某一行（不是点「进入详情」文字）。
- 动画：`@Namespace` + `matchedGeometryEffect`，卡面从行内 `CardFace(large:)` 飞到屏幕**顶部居中**（宽 158 → 屏宽 − 64），`spring(response: 0.42, dampingFraction: 0.86)`。
- 展开：卡面到位后 **+80ms**，下方指标区 / 走势 / 账单 / 分期 / 流水以 `opacity 0→1` + `offset y 16→0` 依次淡入（间隔 30ms）。
- 关闭：**下滑手势**或点顶部空白区反向飞回；不使用「完成」按钮。
- 顶部：**只有卡面**，不挂 toolbar；「编辑」降级为卡面下方一行 12pt 文字按钮。
- 形态：`.overlay` + `Palette.page` 全屏不透明，**不是 sheet**，没有把手、没有半层。

### 4.3 分期录入字段减负（第 9 条剩余）

本轮已删「已享减免」与 5 处解释文字，剩「名称 / 总共几期 / 含利息 / 下一期还款日」四个字段。下一批可再收一档：把「名称」从独立行改成账户行右侧的次级入口（多数情况留空即可），让一屏只剩 3 个真需要填的数。

### 7.1 配色两条为什么必须一起解，不能拆

第 1 条和第 2 条不是两个问题，是同一个关系的两端：

- 页面底 `#F6F6F6` 与白卡只差 **8.5% 亮度**，我上一轮又把阴影从 `rgba(29,28,26,.10)` 压到 `.05`、卡堆前景阴影压到 `.025`——**底和卡的距离被我自己抹掉了**，所以「更不对」很可能不是灰白错，是**层次被我压平了**。
- 记一笔的重点色 `#3ABF58` 亮绿放在这套浅灰里既不够深（描边看得见、字看不见），又和「收入绿 `#2E9E6B`」语义撞车——同一个绿在一个记账 App 里同时表示「选中」和「收入」，必然别扭。

所以下一轮**先定关系再定色值**：卡片靠什么浮起来（色差 / 阴影 / 描边，只能主用一个）、主色在记一笔里到底承担「选中」还是只承担「主按钮」。这两个关系定了，色值才有意义；否则又是换 hex 的循环。

### 7.2 下一轮的硬前提：一张当前构建的真机截图

前四轮反复翻车的共同原因是**我拿 HTML 原型当依据**，而 SwiftUI 实际渲染（`.continuous` 圆角、`.shadow` 半径、`systemGray` 替换、动态字重）与 CSS 有可见差异。下一轮改配色前，需要一张装完 `DooDoo-unsigned.ipa` 后的首页 + 记一笔真机截图，直接按实图改。
