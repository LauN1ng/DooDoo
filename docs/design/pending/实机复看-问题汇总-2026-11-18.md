## 0. 一句话结论

**「一般」不是配色问题。** 配色（D 方案）在真机上已经成立：折线是红的、开关是墨的、按钮是白底描边的、涨跌是红绿的。

问题是三件与配色无关的事：**① 代码没落完（4 处）；② 钱在全 App 里没有统一权重（首页最小）；③ 折线把「没有数据」画成了「事故曲线」。**

## 1. 代码没落完（这四条是缺陷，不是设计）

### P1 · 首页「＋ 记一笔」是裸文本，零示能

| | |
|---|---|
| 实测 | 该行区域白底 **90.2%**、非白像素仅 **2.5%**（就是文字本身）、上下边缘 y2330/2340/2350 最暗值全是 **231**（无描边、无底色） |
| 位置 | `11-home-empty` y2375–2412，字高 12.3pt |
| 根因 | 原型里画了浅色 pill，代码 `DayCardView.addRow` 只有一行 `Text`。**我画了没落。** |
| 修法 | 纸底 `#E9E4D9` + 墨字，或白底 1pt `#D6CFC0` 描边（与 D 方案按钮同构） |

这一条最严重：**全屏唯一能点的东西，看起来最不像能点**，与「记账不打断」直接冲突。

### P2 · `06` 录账单 / `07` 编辑账户 还是系统 grouped 冷灰，磨砂被挡住

| | |
|---|---|
| 实测 | `06` 页底 **`#F2F2F6` 占 51.2%**；`13` 设置页页底 `#F7F5F1` 占 74.8% |
| 根因 | `SettingsView` 有 `.scrollContentBackground(.hidden)` + `.background(Palette.page)`；`BillEntrySheet` / `AccountEditor` 是**裸 `Form`** |
| 旁证 | `AccountEditor.swift:6` 注释原文：「M2a 用系统 `Form`：字段先对齐 PRD 第八节，**样式留到 M4**」 |
| 修法 | 两个面板各加两行，与 `SettingsView` 一致 |

**三套材质那套冷灰，恰恰留在两个最常用的录入面板上。**（我上一轮说「磨砂落了但被盖住」——准确说法是**这两处根本没加那两行**，`glassSheet()` 只改了 sheet 呈现方式，改不了 `Form` 自己的背景。）

### P3 · `08` 存量分期底部一条灰带压着内容

| | |
|---|---|
| 实测 | 竖直取样 x=600：y2100–2160 `#FFFFFF` → **y2220–2340 `#CCCCCD`（约 53pt 整条）** → y2400–2460 `#ECEBE9` → y2520+ `#F7F5F1` |
| 现象 | 「下一期还款日 2026 年 11 月 25 日」和下面两行提示文字**透过**灰带还能看见 |

| 修法 | 待查：footer 需要不透明底，或改成单层 safeAreaInset |

### P4 · 存量分期主按钮仍是实底，D 方案漏了这一处

| | |

## 2. 钱的权重没有统一（「一般」的主因）

### P5 · 首页：日期比钱大

| 元素 | 实测字高 | 推算字号 |
|---|---|---|
| **日期「18」** | **24.0pt** | **32pt** |
| **今日支出 191.00** | **12.3pt** | **16pt** |
| 流水行金额 | — | 14pt |

**一个记账 App，数日期的字是数钱的两倍。** 这是 11-17 诊断的第一条，中间被七轮配色争论盖过去，至今没改。

### P6 · 跨页：同一个「钱」差 2.3 倍

| 页面 | 元素 | 字高 | 字号 |
|---|---|---|---|
| `10` 微信详情 | **余额 4,545.00** | **28.0pt** | ≈39pt |
| `12` 招商详情 | 欠款 500.00（三列） | 12.7pt | ≈17pt |
| `11` 首页 | 今日支出 191.00 | 12.3pt | 16pt |
| `11` 首页 | 流水行金额 | — | 14pt |

**首页是门面，却是钱最小的那一屏。** P5 只是它的一种表现；真问题是**没有一张全局权重表**：

```
余额 / 欠款（详情页首屏）  ≈ 39pt
今日支出（首页首屏）        16pt   ← 反了
行金额 / 三列              14~17pt
```

### P7 · 空账本时一张 704pt 的白卡里只有一句话

| | |
|---|---|
| 实测 | 白卡 **377.7 × 703.7pt**（y417–2528） |

## 4. 结构与注释

### P11 · 详情页六个白卡同圆角同白，无组间节奏

`12` 的白块（y 起点）：三列 1022 / 额度条 1220 / 走势 1378 / 往期账单 2001 / 分期 2282 / 流水 2564。
六个块**圆角一样、白一样、间距一样**，读不出组。缺的是：标题→卡 8pt、卡→卡 10pt、组→组 20pt 这种三级节奏。

### P12 · 注释在回潮

| 位置 | 内容 |
|---|---|
| `12` 走势下方 | 两行 8.7pt 长注：「按流水折算的月末欠款。分期与账单不在曲线上——顶部欠款 = 曲线末尾 + 未记账单与分期。」 |
| `12` 三个空态 | 「还没录过往期账单」「这张卡没有分期」「这个月这张卡没有流水」 |
| `08` | 「账单把利息单列了 / 只有一个合计，直接填上面」等逐行解释 |

与 11-17 定下的「让布局本身发挥解释作用」直接冲突。**一屏三句空态 + 两行长注 = 注释在替设计说话。**

### P13 · 额度条只有 5pt 高

实测 y1220–1235 = **5.0pt**。已用 50%（墨色实心 x60–629，总宽 380pt），但 5pt 的高度在这个页面上接近一条分隔线。

### P14 · 空值三种写法

| 位置 | 空值写法 |
|---|---|
| `12` 三列 | 破折号 `—` |
| `12` 分期 | `0 笔 · 剩余 0.00` |
| `12` 流水 | `0 笔 · 支出 0.00` |
| `13` 设置 | `还差 57 笔` / `1 笔` |

`—` 与 `0.00` 混用，同一个"没有"有四种表达。

## 5. 口径（数据层面的不一致）

### P15 · 同一个数两种颜色

| 位置 | 值 | 颜色 |
|---|---|---|
| 资产页「我有」 | 5,968.84 | **绿 `#1F7A52`**（`NetWorthCard` 新增 `tone`） |
| 储蓄组「余额合计」 | 5,968.84 | **墨 `#1D1D1F`**（`AccountGroupView:66` `isLiability ? expense : ink`） |

我上一轮只给总览卡上了色，组头没跟上。**同一个数，一绿一墨。**

### P16 · `07` 花呗额度是 0.00，详情页进度条就消失了

实测 `12` 是额度 1,000 欠 500（正常）；但 `07` 编辑账户里花呗「额度 0.00」。额度为 0 时进度条没有分母，`12` 那种「已用 50% / 可用 500.00」整块会不见。

**要确认这是真实数据还是没填** —— 如果是真实（花呗不提额），那额度条需要有"无额度"这个状态，而不是消失。

### P17 · 首页「支出 191.00」与列表里的转账/还款

日卡顶部支出 191.00，但列表里有转账 100、1000 和还款 1,250。口径本身是对的（转账还款不计支出），但**页面上没有任何地方说明这一点**，读起来像算错。
