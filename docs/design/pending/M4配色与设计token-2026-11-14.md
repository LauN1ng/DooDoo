### 「都一般般」的四条根因（按可操作性排序）

1. **六版只换了背景。** 卡内图标槽仍是暖灰 `#F3F0EA`、标签底/卡内次级容器没跟着 token 走、分隔线只随 page 微调——所以看起来像「同一张白卡换了六张桌布」。这是本轮原型的实现缺陷，不是你的错觉。
2. **灰阶只有 2 级**（`page` + `slot`）。真正的灰白体系是 **4–5 级冷中性梯度**：页面底 / 卡片白 / 卡内 inset 槽 / 分隔线 / 文字三级，且全程无黄调。
3. **基线选偏了。** 我 D 用 `#F5F5F7`（Apple 灰白，偏亮偏蓝紫，像系统设置页），而你自己选过的是 `#F2F2F3`（更明确的中性浅冷灰）。
4. **更根本：视觉重量与主色缺失。** `记一笔规格冻结-v1.0.md` 第 16 行把 `--accent` 定为**默认墨黑 `#1D1C1A`**，所以六版里品牌绿只出现在「＋ 记一笔」一个按钮上。11-08 那份文档早就指出参考图是「一个饱和主色贯穿」。**只调底色解决不了这条**——这才是「一般般」的主因。

## 一、结论先行（六版出稿时的原始判断，保留作过程记录）

1. **现有底色其实不是纯白**：代码里 `Palette.page = #F7F5F1`（暖白），`FlowView.swift:36` 与 `AccountDetailSheet.swift:49` 都用它；页头与状态栏按规格第 226 行也必须是这个色，不能用系统白。所以本轮把 **A = 现状暖白** 与 **B = 纯白对照基线** 同时给出，请你在真机/截图上确认「现有白底」指的是哪一个。
2. **现状的灰字层级不合格**：`sub #A8A39A` 在白卡上只有 **2.51:1**（WCAG AA 要 4.5:1），`faint #C6C2B9` 1.78:1。PROGRESS 里那条「9.5pt 红字够不够醒目」不只是字号问题，是**对比度本身就不够**。token 必须先修这个，再谈逐屏。
3. **换底色会连带三件事**，实测两个反例：
   - 纯白底 B 与白卡**色差 0%**，卡片边界只能靠描边 + 阴影撑起来；
   - 深暖灰 F 若沿用旧 tab 槽 `#EBE7E0`，与页底**色差仅 3.7%**，直接踩中规格「浅色容器浮白卡色差 <5% 必然糊」这条被否过两次的硬约束 → 槽色必须同步加深到 `#DFD9CD`（16.3%）。
4. 六版里 **B / C / D / E / F 的灰字都已拉到 ≥4.5:1**，A 保留原值只作对照锚点。

## 二、变量与判据

本轮只动 **4 个变量**：页面底色 / 卡片白 / 灰字层级 / 阴影与描边。其余（几何、圆角、字阶、图标、金额色、卡面彩色）一律不动。

| 判据 | 来源 | 阈值 |
|---|---|---|
| 文本对比度 | `ui-ux-pro-max --domain ux`、`ios-hig-design` 第 3/6 节 | **≥ 4.5:1**（正文） |
| tab 槽 vs 页底色差 | 首页规格第 58 行「浅色容器浮白卡必糊」 | **≥ 5% 且槽必须更深** |
| 页底 vs 白卡色差 | 规格第 226 行真机验收 | 越大越不靠阴影；0% 必须加描边 |
| 触摸目标 | `ios-hig-design` 第 1/6 节、`ui-ux-pro-max --domain ux` | **44 × 44pt** |
| 最小字号 | `ios-hig-design` 第 2 节 | **11pt**（现状 9.5pt 逾期红字待修） |
| 动效时长 | `ui-ux-pro-max` | 150–300ms、`prefers-reduced-motion` |

**技能使用记录**：`ui-ux-pro-max` 跑了 `--design-system` / `--domain color` / `--domain style` / `--domain ux` / `--stack swiftui`；`ios-hig-design` 复核 44pt / 4.5:1 / 11pt / Dynamic Type。按 `AGENTS.md` 优先级，其 Web 专属结论（App Store 落地页、Claymorphism 厚边框、Google Fonts 手写体、禁 emoji 图标、hover/cursor/多断点、系统语义色替代硬编码）**一律不采用**；只取可用性规则与 `#F5F5F7` / `#FAFAF9` 两个中性底色候选。

## 五、三层 token 表

### 基础层（不随底色变）

| 组 | 值 |
|---|---|
| 字体 | 系统 SF Pro / PingFang SC；禁止 Google Fonts、禁止手写体 |
| 字阶 | 大数字 32 / 金额 22 / 标题 21 / 正文 14–17 / 次文字 12–13 / 辅助 11（**下限 11pt**） |
| 间距 | 4 / 8 / 12 / 16 / 20 / 24；卡片左右内距 20，卡内文字左右 18 |
| 圆角 | 屏幕 44 / 日卡 24 / 图标槽 13 / tab 17 / 胶囊 15 |
| 层厚 | 首页卡堆 10pt（恒定）；资产卡 16pt |
| 触摸目标 | 44 × 44pt（tab 段现为 36×30，用 `contentShape` 扩命中区，不改视觉） |
| 动效 | 150–300ms；尊重 `prefers-reduced-motion` |

### 语义层（六版差异）

`page` / `card` / `ink` / `ink2` / `sub` / `line` / `slot` / `shadow` / `border` 九个键，取值见第三节。
**固定不变**：`ink #1D1C1A`、品牌绿 `#3ABF58`（只用于交互/功能）、支出 `#C0392B`、收入 `#2E9E6B`、曲线「我有」`#4C8DF6` /「我欠」`#E8734A`、逾期 `#A32D2D`、卡面彩色（内容层）。
**颜色分工**：绿色 = 交互/功能，彩色 = 内容（卡片面、分类图标）。这条不因底色变化。

### 组件层

tab 胶囊 / 日卡 / 流水行 / 资产总览卡 / 负债卡面 / 记一笔按钮 / 标签 / 分隔线。
组件**只引用语义层键**，不得再写裸 hex。现状 `Palette.swift` 只有 19 个色，样式硬编码散在 20+ 视图（`InstallmentEntryView` 84 处、`EntryView` 64 处、`AccountDetailSheet` 64 处），token 定稿后由逐屏那一轮统一收口。
