## 一、先诊断：墨键为什么不搭

**不是位置问题。** D2 那轮已经验证过「只压前卡、层厚带完整从它下方穿过」是对的——控件比整堆卡高一层，卡片一张不少。这个关系不用重开。

**是材质和重量问题。**

| | 整页语言 | 墨键 |
|---|---|---|
| 底色 | 暖白 `#F7F5F1` | — |
| 主体 | 白纸卡 `#FFF`，圆角 24，极轻双层阴影 | — |
| 强调色 | 红 `#C0392B` **只给支出**，用量 < 5% | — |
| 层叠 | 若有若无的纸叠 | — |
| 导航 | — | **`#1D1C1A` 纯黑实心胶囊 126×40** |

墨键是全屏第二重的元素（仅次于 FAB），一个孤立的、与纸毫无关系的黑色硬件。HeyCost 那类 App 的 tab **几乎不可见**——墨键比它重太多，也比 DooDoo 自己的纸卡语言重太多。

**真正的病灶是两个黑物之间的关系**：墨键与右侧黑 FAB 分居屏幕两端，**中间 178pt 空地，两者之间没有任何材质呼应**。读起来像两件不相干的东西被塞在一起，而不是一套导航。

## 二、五版方案

同一套卡堆 + 便签，只换底部导航的**材质**，不动位置、不动数量、不动图标。

| | A 浅底托 | **B 纸签** | C 玻璃 | D 墨键（现状） | E 顶栏 |
|---|---|---|---|---|---|
| 形态 | 3 枚 34pt 浅底圆角方托 | 3 张 40×36 独立纸签 | 124×40 玻璃胶囊 | 126×36 纯黑胶囊 | 页头右侧 3 图标 |

## 三、各版要点

### A · 浅底托

每个图标一枚 34pt 浅底圆角方托，选中项底托转白 + 图标加深 + 顶部一条 12pt 墨线。

- **为什么不是裸图标**：裸图标直接压在层叠边缘上会和纸边混读（第一版实测）。浅底托用**和 emoji 的 42px 浅底圆角容器同一套语言**托住它。
- 选中标记放**顶部**而非底部：底托只有 34pt，底部放标记会与 20pt 图标挤在一起。

### B · 三张独立纸签 ✅ 推荐

三张 40×36 独立小纸签，选中那张**填墨**。

```css
.navB{position:absolute;left:16px;bottom:48px;z-index:60;display:flex;align-items:center;gap:7px}
.navB i{width:40px;height:36px;border-radius:11px;display:grid;place-items:center;
       background:#FCFBF8;color:#A8A39A;
       box-shadow:0 0 0 1px rgba(29,28,26,.13),0 2px 4px rgba(29,28,26,.06)}
.navB i.on{color:#fff;background:#1D1C1A;
       box-shadow:0 0 0 1px rgba(29,28,26,.13),0 4px 10px rgba(29,28,26,.20)}
```

**它同时解掉两个问题**：

1. **材质归位**：纸签用与卡堆后层**完全相同的配方**（`0 0 0 1px rgba(29,28,26,.13)` + `0 2px 4px rgba(29,28,26,.06)`），所以它读成"另一张小纸"，而不是"贴在纸上的黑色控件"。底色用 `#FCFBF8` 而非纯白——纯白签浮白卡就是白浮白。
2. **两个黑物互相呼应**：选中签填墨后与右侧黑 FAB 同为 `#1D1C1A`，**重量对等、语义不同**（导航 vs 主动作）。不再是 D 那种"两个不相干的黑块"。

**选中态用填墨，不用抬起**：白纸签上「抬起 4pt」完全读不出来（第一版实测，白底 + 浅投影的抬起幅度在缩略图上不可见）。只有填充色变化是**明度差**，稳。

### C · 玻璃胶囊 ❌

玻璃 + 淡墨图标，最接近 `index.html` 最初的形态。

**实测不成立**：底色 `rgba(246,243,238,.92)` 与白卡只差 **2%**，胶囊边界读不出，读成"白卡上贴了张白纸"。

> 这是「**白浮白行不通**」这条老教训的又一次复现（首次出现在 nav-layer2 的 B 版）。已否决两次，不要再来第三次：**任何浅色容器浮在白卡上，色差低于 5% 就必然糊。**

### D · 墨键（现状）❌

纯黑实心胶囊 + 独立黑 FAB。两个纯黑重物分居两端，中间 178pt 空地。位置关系（D2 已验证）是对的，但**两个黑物之间没有材质呼应**——这才是"不搭"的真正来源。

### E · 顶栏

tab 进页头右侧（18px 细线图标 + 选中墨点），底部只留 FAB。卡堆层叠**零遮挡**，最干净。

- **代价一**：单手够屏幕顶最难，而资产页是重度页面，每次切过去都难受。
- **代价二**：页头要同时容纳 logo + tab + 便签，三者会挤。原型用 `.vE .note{top:6px}` 把便签下移让开，但便签与页头图标仍偏近。
- 保留为备选，不推荐。

## 四、SwiftUI 映射（B 版）

```swift
// 三张独立纸签，选中那张填墨
HStack(spacing: 7) {
    ForEach(Tab.allCases) { tab in
        Image(systemName: tab.icon)
            .font(.system(size: 17, weight: .regular))
            .foregroundStyle(tab == .ledger ? Color.white : Color(hex: 0xA8A39A))
            .frame(width: 40, height: 36)
            .background(
                RoundedRectangle(cornerRadius: 11)
                    .fill(tab == .ledger ? Color(hex: 0x1D1C1A) : Color(hex: 0xFCFBF8))
            )
            .overlay(
                RoundedRectangle(cornerRadius: 11)
                    .strokeBorder(Color.black.opacity(0.13), lineWidth: 1)
            )
            .shadow(color: Color.black.opacity(tab == .ledger ? 0.20 : 0.06),
                    radius: tab == .ledger ? 10 : 4,
                    y: tab == .ledger ? 4 : 2)
    }
}
.padding(.leading, 16)
.padding(.bottom, 48)
```

要点：

- **纸签投影用 `strokeBorder` + `shadow`，不要用 `stroke`**——`stroke` 会往内描 0.5pt，缩小视觉尺寸。
- 圆角 11pt 与卡片的 24pt、emoji 容器的 13pt 形成三级，不冲突。
- 三个 tab 高度固定 36pt，**不随选中态变化**——变高会推动整排，破坏"卡片一张不少"的静止感。

## 五、与单日多笔约束的关系

`3.5.3` 定的**卡片下内边距 ≥76pt** 是按 FAB 位置算的。B 版 tab 高度 36pt、`bottom:48`，**顶在距屏底 84pt**，低于 FAB 顶 110pt ⇒ **不会比 FAB 压得更深，76pt 仍然成立**。

但若选 E（顶栏），底部只剩 FAB，`bottom:34`（距屏底 80pt），下内边距可放宽到 **48pt**，多出 28pt 给列表——这是 E 版唯一的实质优势。

**tab 栏定案后必须重跑一次几何测量**（与 3.2 的留白测量同一纪律）。
