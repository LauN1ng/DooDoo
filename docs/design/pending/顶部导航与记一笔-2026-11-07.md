### 2.4 tab 与「本月」便签的间隔（2026-11-07 定案）

**问题**：便签贴在日卡内部（`right:6; top:-14`，带 `rotate(-3deg)`），卡堆顶 100 时它的视觉顶在 **83.6**，而胶囊底在 **86** —— 两者**重叠 2.4pt**，截图上看就是便签钻到胶囊底下。

**解法**：只把卡堆顶从 100 下移到 **116**，不碰胶囊、不碰便签、不碰层厚（10pt×3 不变）。

| 项 | 改前 | 改后 |
|---|---|---|
| 卡堆顶 | 100 | **116** |
| 便签视觉顶（含旋转外扩） | 83.6 | 99.6 |
| 胶囊底 | 86 | 86 |
| **胶囊底 ↔ 便签顶** | **−2.4（重叠）** | **+13.6** |
| 卡片高度 | 698 | 682 |
| 便签露出卡顶的高度 | 16.4 | 16.4（不变） |

**为什么是 116 而不是更小**：便签 bbox 顶 = 卡堆顶 − 14 − 3.6（3° 旋转把宽 70 的纸条两端抬高约 3.6pt）。要 ≥12 就得 ≥ 115.6，取整 116，余量 1.6。

**代价**：卡片矮 16pt（698→682）。今日 8 笔仍不溢出（rows 可视高约 547，内容 8×64=512），可接受；换来的是页头右侧「控件—便签—卡片」三段各有呼吸，不再糊成一坨。

### 2.3 为什么这次能做顶部

1. **便签已挪进日卡内部**（`right:6; top:-14`，跟着「今天」这张卡走），页头右侧是空的——上一轮否掉顶部方案时，那个位置被便签占着。
2. 参考图给的是「一枚槽 + 一块亮块」，占 112×34，**不是整屏顶栏**，不构成导航条，也不违反「单手够屏幕顶最难」的顾虑（它不是高频重操作）。
3. 明度方向必须反转：参考图是深卡上更浅的槽；本 App 暖白底上，槽要比页底**更深**，否则就是被否过两次的「白浮白」（色差 <5% 必糊）。

## 三、记一笔（四版）

| 版 | 形态 | 尺寸 | 位置（距屏幕底） | 卡内 `padding-bottom` | 实测间隙 | 结论 |
|---|---|---|---|---|---|---|
| A 变小变轻 | 圆 | 44 × 44 | right 18 / bottom 54（顶 98） | 72px | 20 | 最轻，但底部独苗时最易被忽略 |
| **B 文字胶囊** | 图标＋文字 | 92 × 40 | right 18 / bottom 56（顶 96） | 70px | 20 | **推荐**：唯一不用猜的方案 |
| C 金额入口 | 金额＋plus | 127 × 44 | right 16 / bottom 56（顶 100） | 74px | 20 | **与卡头 −¥165.00 重复**，不推荐 |
| D 卡内纸签 | 纸面行 | 322 × 36 | right 34 / bottom 54（顶 90） | 64px | 20 | 语义最好，但只在「今天」成立 |

**四条共同约束（已实测）**

1. **不压层厚带**：卡下沿 38pt，四版控件底边均 ≥54pt，层厚带（38→8，每层 10pt）完整露出。
2. **间隙 ≥12pt**：四版实测均为 20pt（`padding-bottom` 按版本重算，不再沿用旧的 76pt）。
3. **C 的重复问题**：卡头「支出 −¥165.00」是首页主数字，按钮里再写一遍会让用户怀疑哪个是真的；角落比卡头更重，等于把主数字搬到角落。
4. **D 的日期语义**：翻到历史日时按钮必须变成「给 X 月 X 日补记」，否则会记错日期；而且它随卡堆翻走，不再是全局入口。

**内边距公式（实现时照用）**

```
padding-bottom = (控件顶到屏幕底) − (卡下沿到屏幕底 38) + 12
A: 98 − 38 + 12 = 72      B: 96 − 38 + 12 = 70
C: 100 − 38 + 12 = 74     D: 90 − 38 + 12 = 64（D 是卡内按钮，64 = 36 按钮 + 12 间隙 + 16 内距）
```

> 第一轮四版（变小变轻 / 文字胶囊 / 金额入口 / 卡内纸签）被否，判词「和首页风格不符」。

> 原型：`design/current/entry-bcd.html`（左三格是入口，第四格是三版共用的目的地）；调研依据 `research/记一笔入口调研-2026-11-08.md`。

**B 已定案（2026-11-08）**。理由不是好看，是结构与语义：它与 8 条流水行共用同一节奏（42 槽 + 14pt 字），读成「账本的最后一行」而不是按钮；而且是唯一每张日卡自带入口的方案，补记历史日不需要额外交互。

**第四格（点下去之后）**：三版进入同一张**半屏记账面板**——顶 216（高 628），支出/收入/还款/转账 → 金额 0.00 → 8 分类 4×2 → 账户药丸 → 评分四档 → 16 键键盘（完成键嵌在右下）。入口形态不改变目的地，所以这个决策只关于首页长什么样。

### 3.2 卡堆：张数上限、首次使用与层厚（2026-11-08 新定）

> 用户补充的规则：**首页卡堆最多 7 张；首次使用只有 1 张，不是直接 7 张**。账户堆同理。
> 原型：`design/current/home-v3.html`（顶栏可切 1 / 2 / 4 / 7 张，并可开「首次使用」空账本）。

**四条规则（2026-11-08 修订：可见层封顶 4 张）**

1. **张数 = min(要显示的天数, 7)**；首次使用 / 只有 1 天数据时**只有 1 张**，不补空卡。
2. **层厚恒定 10pt**，不做自适应压缩（压到 5pt 比 24pt 圆角还薄，读不出层）。
3. **可见层封顶 4 张（3 条边）**：7 张全画出来就是 6 条等距白边，读成「一沓空白卡片」——实测难看（见 3.4）。更深的卡不渲染。
4. **前卡底距屏 = max(34, 8 + 10×min(N−1,3))**，**卡高 = 720 − (前卡底距屏 − 8)**；卡顶永远 116，只有下沿动。

| 张数 N | 画出的卡 | 层厚带 | 前卡底距屏 | 卡高 |
|---|---|---|---|---|
| 1（首用） | 1 | 0 | 34 | 694 |
| 2 | 2 | 10 | 34 | 694 |
| 3 | 3 | 20 | 34 | 694 |
| 4 | 4 | 30 | 38 | 690 |
| 5 ~ 7（上限 7） | **4** | 30 | 38 | 690 |

> N ≥ 5 时外观与 N=4 完全相同——**代价是「有几天」不再靠层数读出**（日期在卡上，滑动也能知道）。这是 3.4 里 S1 的核心取舍，待确认。
> 旧实现（`home-final.html`）固定 4 张、前卡 38、最深 8 —— 正是 N=4 那一行，向后兼容。

**两条实现约定**

- **后层只画纸边、不渲染内容**：层数到 7 时若每层都把流水铺满，等于 56 张 emoji、7 份 DOM。看不见的东西不该存在。
- **便签只在「今天」那张卡**，翻到历史日即消失（沿用 3.5.2 的 R4）。

**资产页（账户堆）同理**

| 账户数 | 层数 | 容器高 | 前卡底距容器底 | 数量角标 |
|---|---|---|---|---|
| 1 | 1 | 84 | 0 | 不显示 |
| 2 | 2 | 100 | 16 | 显示 |
| ≥3 | 3 | **116**（与冻结规格一致） | 32 | 显示 |

层厚沿用 16pt（不是首页的 10pt：资产卡 82 高、圆角 13，10pt 会掉进圆弧读不出层）。已改在 `account-stack.html` 工作副本，冻结快照未动。

### 3.3 需要再改的一处：记账行的「槽」

用户明确：**虚线槽未必是最好**，先记下来以后改。当前实现是 42×42 虚线圆角槽 + 15pt 墨 plus。

待比较的四个替身（下次单独出图，会连带改行的节奏）：

| 替身 | 描述 | 风险 |
|---|---|---|
| B1 虚线槽（现状） | `1px dashed rgba(29,28,26,.18)` + plus | 虚线是全新元素，页面别处没有 |
| B2 空分类位 | 同款 42pt 实底 `#F6F3EC`，只有 plus，无边框 | 最融入，但「空槽」语义弱 |
| 纯文字行 | 无槽，左对齐「＋ 记一笔」13pt | 最轻，但与流水行节奏脱节 |
| 纸面按钮 | 42pt 白底 + 半像素描边（与卡片同材质） | 最像按钮，可能又回到「物体」 |

### 3.4 叠法 4 版（2026-11-08 新出）

> 起因：用户指出 7 张时的堆叠「并不好」——6 条等距白边 = 一沓空白卡片。
> 小图：`design/current/_slots.png`（上排 4 个叠法取样 390×150，下排 4 个槽取样 390×76，都是实际尺寸）。
> 可交互版：`design/current/slot-and-stack.html`。

| 版 | 做法 | 优点 | 代价 |
|---|---|---|---|
| S0 现状 | 7 张全画，层厚 10 | 张数真实 | **6 条白边，读成一沓空白卡**（被否） |
| **S1 只露 3 条边** | 可见层封顶 4 张 | N≤4 与已通过的外观**完全一致**；7 张也不糊 | 「几天」不再由层数读出 |
| S2 锥形收窄 | 每往下一层左右各收 6pt，层厚 12 | 读成「一摞纸」而不是平行线 | 卡宽不再是常数，实现多一个变量 |
| S3 两条边 + 渐隐 | 2 条边 + 底部 26pt 渐变阴影 | 最像照片里的纸堆 | 「几天」完全不可见 |

**默认按 S1 实现**（`home-v3.html` 已改），待确认后写进规格。

## 六、SwiftUI 映射

```swift
// 顶部 tab：自绘分段控件，不用 Picker(.segmented)（系统样式对不齐 34pt / 17 圆角 / 半像素描边）
struct TopTab: View {
    @Binding var tab: RootTab                      // .flow / .assets / .settings
    var body: some View {
        HStack(spacing: 0) {
            ForEach(RootTab.allCases, id: \.self) { t in
                Button { tab = t } label: {
                    Image(systemName: t.icon)
                        .font(.system(size: 17))
                        .frame(width: 36, height: 30)
                        .foregroundStyle(tab == t ? Color.ink : Color.ink.opacity(0.38))
                        .background {
                            if tab == t {
                                RoundedRectangle(cornerRadius: 15)
                                    .fill(.white)
                                    .shadow(color: .ink.opacity(0.10), radius: 1, y: 1)
                                    .overlay(
                                        RoundedRectangle(cornerRadius: 15)
                                            .strokeBorder(.ink.opacity(0.10), lineWidth: 0.5)
                                    )
                            }
                        }
                        .contentShape(Rectangle())
                }
                .buttonStyle(.plain)
            }
        }
        .padding(2)
        .frame(height: 34)
        .background(
            RoundedRectangle(cornerRadius: 17).fill(Color(red: 0.922, green: 0.906, blue: 0.878)) // #EBE7E0
        )
    }
}
```

页头：`HStack { Text("DooDoo").font(.system(size: 21, weight: .bold)) ; Spacer() ; TopTab(tab: $tab) }`
`.padding(.horizontal, 20)`、`.frame(height: 34)`，挂在状态栏下 52pt 处。
