# docs/design/ 设计文档

> 三个子目录 = 三个权威等级。**目录决定了这份文档说了算不算**，不靠文件名里的日期。
> 变更规则见根目录 `AGENTS.md` 第六节。

---

## 一、权威等级

| 目录 | 含义 | 可改性 | 能否据此写代码 |
|---|---|---|---|
| `spec/` | 已冻结的实现依据 | 只能改「明确不锁定」的章节（1.x） | ✅ 唯一可以 |
| `pending/` | 方案未定案 | 可任意改，可继续出对比 | ❌ 不可以 |
| `history/` | 推演记录、被推翻的结论、旧决定 | 只追加，不删旧结论 | ❌ 只作背景 |

**判断一份新文档放哪**：方案对比没做完 → `pending/`；用户拍板并冻结 → `spec/`，同时把推演过程整份转入 `history/`。

## 三、写新设计文档的模板

```markdown
# 主题 · YYYY-MM-DD

> 状态：**待定案** / **已冻结** / **草稿**
> 对应原型：`design/current/xxx.html`（可交互）
> 前置：`docs/design/history/xxx.md`（哪些结论已作废）

## 零、一句话描述
## 一、结构与尺寸
## 二、交互契约
## 三、SwiftUI 映射
## 四、数据契约
## 五、明确不锁定（未验证项显式排除）
## 六、与旧文档的冲突处理
## 七、变更规则
```

**「明确不锁定」这一节是必须的**：把没做过方案对比、没真机验证的东西显式排除，比假装全都定了更可靠（这是 v1.0 冻结时定下的做法）。

## 四、冻结流程（下一步会用到）

1. 方案对比完成、用户拍板。
2. 原型出快照：`design/current/主题-vX.Y.html`，记录字节数与 SHA256。
3. 写 `spec/主题-规格冻结-vX.Y.md`，把「不锁定项」列清。
4. 旧的推演文档移入 `history/`，顶部标注「已冻结，实现读 spec」。
5. 到 `PROGRESS.md` 的冻结物登记表加一行。
