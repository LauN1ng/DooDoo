## 一、列表层已定结构

| 区域 | 内容 | 备注 |
|---|---|---|
| 顶部汇总卡 | `我有` / `我欠` 两个数字 + 各自涨跌百分比 | **不放进度、不放推演**。汇总层只回答"我现在是什么状态" |

## 二、字段归属：什么留在列表，什么下沉详情

| 字段 | 列表 | 详情页 | 理由 |
|---|---|---|---|
| 欠款余额 | ✅ | ✅ | 列表层核心 |
| 本期应还 + 还款日 | ✅ | ✅ | 底线三，必须一眼可见 |
| **还款进度** | ✅ 卡面底线 | ✅ 大图 | 会动、且需要你动 |
| 逾期天数 / 逾期金额 | ✅ | ✅ | 一等警示 |
| 较上月变化 | ✅ 绝对额 | ✅ 百分比 | 绝对额抗账单周期噪音 |
| **额度 / 可用额度** | ❌ | ✅ | 静态背景，不指导行动 |
| **额度使用率** | ❌ | ✅ | 同上；且列表层已有一条进度线，再放一条会打架 |
| 结清月份 / 逐期表 | ❌ | ✅ | 信息量太大，列表塞不下（试过，挤） |
| 额度变更历史（9,000→4,600） | ❌ | ✅ | 只用作详情页背景信息 |

**一条硬规则**：账户行（卡面 + 两列，每列 2 行）就是信息密度上限，第三行必挤。要加指标只有两条路——进卡面图层的绝对定位元素（零行高），或下沉详情页。

## 三、还款进度：定义与契约

**定义**：卡面底部 3px 细条 = `本期已还 ÷ 本期应还`。

| 值 | 含义 | 视觉 |
|---|---|---|
| 0% | 本期一分未还 | 只剩 20% 白底，进度为空 |
| 33% | 还了三分之一 | 白条走三分之一 |
| 67% | 还了三分之二 | — |
| 100% | 本期已还清 | 整条实白 |

- 数据（原型）：招行 0%（8 月账单逾期未还）、花呗 67%、e招贷 100%、白条 33%
- 储蓄卡 / 余额宝无此概念，不显示
- **为什么用它替掉额度使用率**：额度是静态背景（借多少决定你会不会出事，但不是你每月要做的事）；还款是每月动作。列表层只放"会动、且需要你动"的指标。
- **配套改动**：右侧第二列标签由「下期应还」改为「**本期应还**」。不改会出现"进度是本期、金额是下期"的错位，两个数不是一回事。

## 四、配色规则：红涨绿跌

- **涨 = 红，跌 = 绿**（与 A 股一致），按方向配色，不按好坏。
- 应用全域：汇总卡涨跌、支出较上月、单卡较上月绝对额、储蓄较上月。
- **唯一例外**：还款进度线不用红绿，用白色 —— 进度不是涨跌，不参与这套语义。
- **已知副作用（保留）**：`余额宝 ↗1.8%` 是收益增加，但涨=红，看着像警报。若日后觉得误导，最小补救是给"余额类账户"的涨幅降成中性灰，而不是推翻红涨绿跌。

## 五、账户详情页规格（本轮不画，先定规格）

参考 Copilot Money 账户详情页（2026-11-06 截图）。逐层映射如下：

| Copilot 元素 | DooDoo 对应 | 说明 |
|---|---|---|
| 居中卡图（红色 BofA 卡 + 尾号） | 同款卡面放大版 | 直接复用列表卡面的 `--c1/--c2` 变量 |
| 账户名大字 `Adv Plus Banking` | `招商银行 8857` | — |
| 两列：AVAILABLE / CHANGE | `可用额度 1,480.00` / `本期应还 665.36` | **额度放在这里**（4,600 − 3,120） |
| 大面积阶梯折线 + 渐变填充 + 端点圆点 | 欠款余额走势（近 1 年，按月） | 阶梯感天然贴合账单周期 |
| 区间 pills `1W/1M/3M/YTD/1Y` | 保留 | 1W/1M 对账单周期有用 |
| `Latest update received ...` | 最后对账时间 | **对底线一有效**：让你知道数据新不新 |
| GOALS 分组（3 条带图标） | **账单期 + 分期序列** | 逐期一行：期号 / 金额 / 日期 / 本金 / 利息，可点开改 |
| `Manage connection` 按钮 | 编辑账户 | 额度、账单日、还款日 |

### 详情页三个硬约束

1. **逐期表必须校验**「各期本金合计 = 初始本金」，对不上不允许保存（抄 MoneyWiz）。
2. **额度要带历史**：2025-12 为 9,000，2026-08 起为 4,600（PRD 账户模型 `originalLimit`）。额度变更只作背景，不做提示。
3. **折线必须可解释**：欠款曲线在账单日上跳、在还款日下跳，这两个事件必须在图上标记，否则用户会以为数据错了——这会直接击穿"余额对得上"的信任。
