## 零、一句话描述

**点开一张卡，先看清这个月要还多少、它由哪两半组成，再往下看欠款怎么走到今天，最后看账期和分期明细。**

三个必须回答的问题，按顺序落在首屏：

1. 我欠多少、还剩多少额度 —— 三列第一列 + 额度进度条
2. 这个月 22 号要扣多少钱 —— 「本月要还」白条
3. 这些钱里哪些是分期 —— 三列第二、三列

## 二、页面结构（从上到下，顺序即优先级）

```
0  系统状态栏               52pt
1  导航条                   52pt   ‹ 招商银行 8857  ⋯
2  卡面                     现有信用卡样式，不改
3  账户名                   「招商银行 8857」居中
4  逾期提示（条件渲染）      「逾期 82 天 · 2026-08 期 512.80 未还」红字
5  指标区                   三列 + 额度进度条 + 本月要还白条
6  欠款走势图               + 图注 + 区间切换 + 最后对账
7  往期账单                 3 期（不含当期）       › 进全部账单
8  分期                     3 笔                  › 进分期详情
9  流水                     本月 / 全部 分段
10 编辑账户                 底部按钮
```

**区块顺序的判据**：越靠上越是「现在要做的动作」。走势图是解释过去的，所以它必须排在指标之后、明细之前，**不得上移到卡面下方**——那会把「本月要还」挤出首屏，违反底线 3。

**卡面底部那条白色进度线保留**（现有卡面设计的一部分），它和第五节额度进度条表达同一件事，但一个属于卡面视觉、一个属于数据，并行存在不算重复。

## 三、指标区

### 3.1 三列（并列，等宽）

| 位置 | 标签 | 数值 | 副标题 | 颜色 |
|---|---|---|---|---|
| 第一列 | 欠款 | `3,120.00` | `额度 4,600.00` | 红 `#C0392B` |
| 第二列 | 本期消费 | `665.36` | `不含分期` | 主文字 `#1D1C1A` |
| 第三列 | 本月分期 | `449.67` | `3 笔 · 同一天还` | 主文字 `#1D1C1A` |

- 三列等宽，`HStack` 内每列 `frame(maxWidth: .infinity)`。
- 数值 **17pt / semibold / tabular-nums**，三列字号必须一致。两列时用 21pt，三列必须降到 17pt，否则 8 字符金额会挤在一起。
- 标签 10.5pt `#9A968D`，副标题 9.5pt `#B0ACA3`，均不换行。
- 三列上间距 18pt。

**第二列必须叫「本期消费」，不能叫「本期要还」。** 本期账单是 1,115.03，第二列只是账单里非分期的那一半；叫「本期要还」会和下面的账单数字直接打架。

### 3.2 额度进度条（通栏，贴在指标下方）

| 元素 | 规格 |
|---|---|
| 轨道 | 高 5pt，圆角 3pt，底色 `#E9E4DA`，通栏宽（左右 3pt 内缩） |
| 填充 | 主文字色 `#1D1C1A`，宽度 = 已用比例（本例 68%） |
| 左注 | `已用 68%`，10pt `#9A968D` |
| 右注 | `可用 1,480.00`，数值 11pt semibold，`#6B6862` |
| 上间距 | 距三列 15pt；轨道与注释间距 8pt |

- 进度条**不写「3,120.00 / 4,600.00」**。欠款已在第一列、额度已在第一列副标题，这里再写一遍就是同一个数第三次出现。
- 进度条删掉了原「额度」独立区块，所以原区块里的「2026-08 由 9,000 下调至 4,600」移至走势图图注（第四节）。

### 3.3 「本月要还」白条（指标区最后一条）

| 元素 | 规格 |
|---|---|
| 容器 | 白卡，圆角 14pt，内边距 11×14pt，上间距 10pt |
| 左文字 | `本月要还 · 11/22 一笔还清`，11pt `#9A968D` |
| 右数值 | `1,115.03`，14.5pt semibold，tabular-nums |

这条白条是**详情页唯一的合计落点**，也是能从资产页那个整组合计里核出来的那个数。不得删除、不得只写「账单 1,115.03 · 分期 449.67」这种需要心算的副标题形式。

## 八、数值口径（最容易做错的地方）

### 8.1 恒等式

```
本期账单 dueAmount  =  本期消费  +  本月到期分期
        1,115.03    =    665.36   +     449.67
```

**「本月要还」= 本期账单金额 = 1,115.03。**

### 8.2 禁止的算法

```
本月要还 = Σ(本期消费) + Σ(本月到期分期)   ← 错，分期被算两次
```

分期到期额**本来就进当期账单**，它不是账单之外的独立欠款。用上式会把 449.67 加两遍，本月要还变成 1,564.70，并顺着把资产页整组合计一起带偏。

实现时必须从 `BillStatement.dueAmount` 直接取「本月要还」，**不得**由分期与消费反向加总。

### 8.3 逾期

- 逾期金额**不计入**本月要还（PRD 9.12）。
- 逾期只在两处出现：顶部红字（警示）+ 往期账单行（明细）。
- 逾期金额必须与本期消费金额不同数。原型曾出现两者都是 665.36、同一屏两个 665.36 指两件事，已改为 512.80。

### 8.4 引用快照数据（招行 8857，2026-11-12）

| 项 | 值 | 备注 |
|---|---|---|
| 欠款 | 3,120.00 | 含息口径 |
| 额度 | 4,600.00 | 2026-08 由 9,000 下调 |
| 已用 | 68% | |
| 可用 | 1,480.00 | |
| 本期账单 | 1,115.03 | 11/22 到期，剩 10 天 |
| 本期消费 | 665.36 | 不含分期 |
| 本月分期 | 449.67 | 3 笔：128.00 + 216.67 + 105.00 |
| 逾期 | 512.80 | 2026-08 期，8/22 到期，82 天 |
| 剩余分期总额 | 2,806.35 | 1,408.00 + 1,083.35 + 315.00 |

## 十一、v1.0 明确不锁定（留给 1.x）

1. 逾期金额超过 1 期时顶部红字如何折叠（多期逾期）。
2. 无分期账户的指标区形态（第三列为 0 或整列隐藏，未定）。
3. 储蓄 / 现金 / 借款账户的详情页形态（本规格只覆盖信用账户）。
4. 走势图区间切换后的数据粒度（1周 / 1月 的数据源未定）。
5. 流水「全部」模式的加载策略与分页。
6. 分期详情页、账单列表页、改金额弹层的全部交互（见第一节）。

## 十二、变更规则

- **1.x 小版本**：只可改第十一节标注未锁定的内容，且在本文末追加修订记录。
- **2.0 大版本**：改三列内容、改区块顺序、改第八节口径 —— 必须先经用户确认，出新快照 `account-detail-v2.0.html` 与新规格，本文件标 `已废止`。
- 快照 `account-detail-v1.0.html` 的 SHA256 是冻结契约的一部分。**移动可以，改内容不行。** 改文件后哈希变为即视为毁约。
