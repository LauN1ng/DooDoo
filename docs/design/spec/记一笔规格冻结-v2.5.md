## 三、卡面（CardFace 六层，全部代码画，不用位图）

| 层 | 内容 |
|---|---|
| 1 | 基色渐变 142°，`c1 → c2`（品牌只存两个色值） |
| 2 | 左上径向高光：`radial 120% 90% at 8% -10%, rgba(255,255,255,.30) → 0 55%` |
| 3 | 斜向光带：112°，三道半透明白（.12 / .09） |
| 4 | 金属芯片：19×14 圆角 3.5，金色三色渐变 `#F0E3B4→#C9A94E→#EFE2B2` + 0.5pt 内十字线 |
| 5 | 0.5pt 白色内描边 `opacity .16` |
| 6 | 深色投影 |

| 尺寸 | 用途 | 圆角 |
|---|---|---|
| 158×100 | 支出/收入/还款的账户选择、转账的双卡 | 16 |
| 112×72 | 还款的「扣款卡」 | 13 |

**选中态（v2.2 改）＝ 亮度 + 前后层次，不用任何彩色。**

| | 未选 | 选中 |
|---|---|---|
| 亮度 | `colorMultiply(Color(white: 0.90))` | 原亮度（`.white`） |
| 尺寸 | `scale .94` | `scale 1.04` |
| 位置 | 下沉 3pt | 原位 |
| 投影 | **两层**：贴地 `0 1 2 .03` + 环境 `0 2 6 .05` | **两层**：贴地 `0 2 3 .22` + 环境 `0 12 22 .13` |

为什么分类的「物理抬起」没搬过来：这一排是**同一个东西的不同张**（都是卡），卡面又自带品牌色——在水平排列里抬起会破坏对齐，而「谁站在前面」比「谁被拿起来」更符合一叠卡的实物。所以账户用亮度与前后层次，分类用高度。
为什么不用描边：卡面第 5 层已有 0.5pt 白色高光内描边，再压一圈线会和它打架。
**横滑必须放开裁剪**（`ScrollView` 加 `.scrollClipDisabled()`）：选中卡的环境影 `0 12 22 .13` 要向上借 10pt、向下借 34pt，而这条横滑的垂直内距只有 2pt——不放开的话上下两半影子整个被切掉，只剩左右两侧那 16pt 内距里的部分，读起来就是「阴影跑到左边」。**这是实现约束不是样式偏好，漏掉即 bug**（2026-11-16 真机反馈第 2 条）。

> **2026-11-16 补录（第六次修订）：单层投影改成两层。** v2.4 的 `0 10 18 .22` 是「一团散开的雾」——从 `#89` 真机截图上量：卡底边往下 1pt 处亮度 184（纸底 230），到 8pt 就淡到 213，**底边没有一条贴地的实影**。影子是从卡片外扩出去的、不是落在下面的，所以读起来像印在纸上洇开，不像离地。用户原话「要想浮起来重点是下面那层的阴影」说的就是这个。
>
> 现在拆成两层分工：**贴地** `0 2 3 .22` 半径小、几乎不模糊，负责勾出「边缘离开纸面」这条线；**环境** `0 12 22 .13` 大而软、偏移 12，负责距离感。同一张对比页量到：底边往下 1pt 处 199 → **164**，8pt 处 213 → **208**，硬边和纵深同时有了。侧向渗漏反而比原来小（环境层透明度 .22 降到 .13），不会在相邻卡之间糊成一片。
v1.0 是 2pt `ink` 描边、v2.0 是 2pt 主色描边 + 22% 外投影，两版都靠「画一圈」；v2.2 起这一圈在账户卡上彻底取消。

文字：卡名 12.5/650、副标 9pt、卡号 9.5pt `tabular`、网络标 7pt/700。深色卡文字用白色系（`style.ink` 由 BrandPalette 决定）。

- 支出 / 收入 / 还款：单一金额，键盘直接输入。

## 六、分类两级

**v2.2 起，一级不再是「色块」，是「贴纸」。** 贴纸不垫纸——没有底槽、没有描边、没有主色实底，图标直接落在白卡面上。

| 层 | 规格 |
|---|---|
| 一级（支出） | 8 类横滑：吃/穿/住/行/乐/医/情/其他。**无槽**：图标 36pt + `drop-shadow(0 1 1.5 .10)`，布局框 44×44（HIG 命中下限）、列宽 52、间距 8、标签 11pt |
| 一级（收入） | 2 类：工资、其他收入，同上 |
| **一级选中** | **纯物理抬起**（V1）：`scale 1.22` + 上移 6pt + `drop-shadow(0 7 9 .26)`；**未选中图标降到 80% 不透明**。只用高度（含随高度走的投影）与明度，**不引入任何彩色**：不用描边、不用主色底、不用底部短线、不发光。v2.2 的「弱档径向散射」整条取消，理由见本节末补录 |
| **一级显示二级结果** | **每格显示自己那一类记着的二级**（方案 A）：选「咖啡」→「吃」格变成咖啡图标 + 「咖啡」；切到「穿」时「吃」格仍是咖啡，切回来也不丢。没选过二级的类显示大类自己。**选中态与内容分离**——切走的类照样显示二级，但不会显得被选中。**删除 v1.0 补录的「已选 吃 › 咖啡」回显行**（连带砍掉 16pt 高度） |
| 二级浮层 | 白卡圆角 20、内距 14/10/14；**5 列 × 2 行**、行距 14；**无圆底**，图标 30pt + 微影，整格 48pt 高的热区；标签 10pt |
| 二级选中 | `scale 1.16` + 标签 `ink` 600。**不抬起、不发光**——同屏 8~10 个一起抬会像彩纸屑 |
| 打开方式 | 点一级：同类=开/关浮层，异类=切换并打开；浮层覆盖下方内容，不推挤布局。**格子的内容是二级，身份仍是一级**——点它打开的仍是该大类的抽屉，换大类点旁边任意一格 |

三条约束（不得在实现时自行放宽）：

1. **选中态只看「是不是当前这一族」，内容看「这一族记着什么」。** 两件事必须分开：合起来会让「显示二级」自动等于「被选中」（切走的大类看起来还亮着），或者反过来，一换类就丢掉刚选的东西。
2. **替换发生在原位，不换位置。** 格子仍在第 N 个位置上，抬起也仍在原处——同一次操作只该有一件事在动。
3. **名字长度已实测**：51 个二级里 50 个是 2 字、只有「手续费」「加班费」是 3 字，11pt 下宽 33pt < 52pt 列宽，**不需要缩字号、不需要两行**。若后续新增 4 字以上二级，改用 10pt 并允许 `minimumScaleFactor(.9)`，不允许截断。

为什么二级还是「字」而不是「抬起」：浮层打开时一级那排还露在下面（选中那个已经抬起 6pt），二级再抬就是两层高度互相干扰；而且同屏 8~10 个抽屉一起抬，网格会跳成一片，反而更难找。

> **2026-11-16 补录（第五次修订，不改本节其余文字）**：v2.2 的「弱档径向散射」整条取消，三项实测都对不上——① **色表与图标不符**：`CategoryGlow` 从每个一级 PNG 的非透明像素取平均色相、再统一到 S0.50 / V0.97，但 `吃` 的图标是银紫餐具，吸出来的紫光叠上去让整格发紫；`住` 拿到黄绿 `#E1F77C`（V 0.97），在暖白 `#F7F5F1` 上几乎看不见。② **强度只有 `.28`**，放大又只有 `1.12`（面积仅 +25%），同屏 8 个里那个「亮起来」的找不出来。③ **只往一个方向使劲**：让选中的变大、却没让未选中的变小，眼睛必须逐个比。现在改成 `1.22` / 上移 6 / 未选中 80% 不透明，两头一起动。七版对比（现状 / 纯物理 / 去饱和 / 品牌绿光 / 垫白片 / 绿环 / 合荐）见 `design/current/entry-selection-2026-11-16.html`，用户选 **V1**；`CategoryGlow.swift` 随代码删除。

|---|---|
| 未评分（`nil`） | 21pt 虚线方框（圆角 2.5、线 1.05pt、**dash 按周长等分 14 段**：段长 3.0 + 间隔 2.69、`gradeVacant` 44%）+ 中央加号（臂长 7.2pt、1.35pt 圆头、52%） |
| 已评分 | 22pt 徽章（`SpendGrade.assetName`）+ 右侧 46pt 定宽文字区 |
| 文字 | `SpendGrade.entryTitle`：夯爆了 / 飘了 / 拉完了 / NPC。13pt semibold、tracking 0.2、颜色 `Palette.gradeTint`。**不铺底、不描边**——颜色只由徽章素材自己提供 |

**几何为什么是 21 而不是 28**（这一处别再凭感觉改）：徽章原图 80px、内容 76px、圆角约 8px → 圆角只占内容的 **11.4%**，显示 22pt 时圆角仅 **2.5pt**。旧框 28pt / `rx 6.6` 的圆角占 23.6%，是徽章的两倍。框大一圈、圆角大一倍，眼睛一定读成「一个框罩着一个小图标」——**这才是「虚线处理和图标割裂」的真正成因，不是动画曲线**。21 略小于徽章视觉尺寸（20.9pt + 透明边），能把空位完全盖住。

> **2026-11-16 补录（第六次修订）：虚线改成按周长等分 14 段。** 旧值写死 `dash 2.9 + 2.6 = 5.5`，而这条路径周长是 `4×(21−5) + 2π×2.5 ≈ 79.71`，79.71 ÷ 5.5 = **14.49**，除不尽。虚线绕回起点时相位错开，接缝处并成一根 8pt 的长划线——放大截图里能直接看到「下边比上边长、左边比右边少一段」，这就是用户说的「左右两边看着不对称」，跟圆角、跟素材都无关。改成 14 个周期等分周长后，半周长正好 7 个周期，旋转 180° 图案与自身重合，左右镜像对称。代码里由 `slotDash` 现算（`EntryView`），不再写死数字；同时把 `strokeBorder` 换成 `stroke`，避免内缩让周长跟着线宽变。

**首次评分（空位 → 落第一档 `夯`）** 总 300ms，三者时间上错开、**没有叠加帧**：

| 时段 | 动作 |
|---|---|
| 0–70ms | 加号淡出 |
| 0–130ms | 虚线框收到 `scale 0.18` 并透明（`easeIn`）。**没有模糊**——模糊会和同时出现的徽章糊成一片 |
| 100–300ms | 徽章从 0.72 弹入（`spring(response 0.26, dampingFraction 0.66)`，自带约 6% 过冲） |
| 140–400ms | 文字从「横压 0.84 / 纵拉 1.08」弹回 1（`anchor: .leading`，中文左对齐，从中心缩放会让首字往左爬出图标） |

**换档（已评分 → 下一档，四档循环 夯 → 飘 → 拉 → NPC → 夯）** 只播果冻，**任何换档动画都不会把虚线框带回来**。果冻 440ms 四段：

`(0.80, 0.90)` + `-8°` → `(1.18, 1.08)` + `+5°` → `(0.95, 1.02)` + `-2°` → `(1, 1)`

文字同步做缩水版（幅度减半），锚点同样在 leading。实现必须用 `keyframeAnimator`（trigger 变化时**播一遍就停**）；**不能用 `phaseAnimator`**——它按 phase 循环，图标会一直抖。

**四条硬规则**：

1. 点过之后**永不回到空位**。`nil` 只会在三种情况下重新出现：打开面板、切类型、切到一个没有 `defaultGrade` 的分类。
2. 虚线消失是**彻底**的（直接移除），不是变淡。
3. 首评动画没播完就连点 → 立刻收掉交接态进换档，虚线不得复现。
4. 「跳过」入口取消：不评分就是不点。`nil ≠ NPC` 的语义不变（PRD 9.13）。

**默认带出** `Category.defaultGrade`（PRD 9.13 规则 3）。带出时**不播交接**，只让徽章弹一下。

**尺寸**：徽章 22 / 空位 21 / 文字区 46（定宽，否则切档时左侧备注被顶得抖）/ 徽章与文字间距 6 / 竖虚线 30×1.2（dash 3+3）/ 备注卡最小高 64。评分位点击区 **73×44**，高度卡在 HIG 44pt 下限。

**文案双轨**：`entryTitle`（夯爆了 / 飘了 / 拉完了 / NPC）给记一笔；`title`（夯 / 飘 / 拉 / NPC）留给排行榜这类横向空间紧张的位置。**两者暂时不同步**，排行榜落地时再定是否统一。

收入 / 还款 / 转账不出现评分位。

## 八、保存行为

1. 校验：金额 > 0；还款需有可关联账单期（M3 起）。
2. 写入走 `LedgerService`（AGENTS 7.2），软删除、`recalculateAll()` 照旧。
3. 保存后面板关闭，回到流水页当天日卡，新行在列表顶部高亮一次。
4. 「再记」= 保存后保留面板、清空金额，其余默认值重新带出。
