## 零、一句话描述

资产页分两组（信用 / 储蓄），每组是**一摞实体银行卡 + 右侧汇总数字**；点这摞卡，**整屏盖上一层磨砂玻璃**，底下页面还在、字读不出，浮层里是账户明细列表（左卡面 + 右两列 × 两行）。

---

## 一、三层结构

| 层 | 是什么 | 关键约束 |
|---|---|---|
| 资产页（下层） | 页面本体，始终存在 | 打开浮层时**高度、位置、滚动位置都不变**——不是换页 |
| 浮层（中层） | `inset:0` 的磨砂玻璃 | 必须能透出下层色块轮廓；**不允许任何 sheet 语法**（见 4.1） |
| 明细行（上层） | 卡面 + 两列 | 每列恒定 2 行，第 3 行必挤 |

### 2.3 卡牌堆

> **2026-11-08 定案**：后层**回到账户真彩色**（即 v1.2 的实机判断），2026-11-07 01:00 的"白纸后层"方案**否决**。层厚 16pt、容器 146×116 保留。理由见 2.3.1。

| 项 | 值 |
|---|---|
| 卡尺寸 | **132 × 82**，圆角 13pt（前层后层同为 13） |
| 容器 | 宽 **146**（`flex: 0 0 146`），高 **`84 + 16 × (层数−1)`**；卡在容器内水平居中（`left:50%; margin-left:-66px`） |
| 层数 | **min(账户数, 3)**：`maxL = min(n−1, 2)`；`n = 1` 时只有前卡，不摆空层 |
| 层厚 | **每层下沉 16pt**：`k0 bottom = 16×maxL`、`k1 bottom:16`、`k2 bottom:0` |
| 横向错位 | `k1` 右偏 4pt（`margin-left:-62`）、`k2` 左偏 4pt（`margin-left:-70`） |
| 旋转 | `k1 +0.8°`、`k2 −1.0°`，`transform-origin:bottom center` |
| 后层材质 | **账户自己的 `--c1/--c2` 渐变** + `filter:brightness(.88)`（k1）/ `.76`（k2）；描边 `inset 0 0 0 .5px rgba(255,255,255,.22)`、顶部亮线 `0 -1px 0 rgba(255,255,255,.50)`、投影 `0 2px 6px rgba(29,28,26,.16)` |
| 后层选谁 | 由数据里的 `stack` 字段**手工指定**；不用色相距离算法 |
| 深色卡（`lum < .30`） | 后层改 **`brightness(1.22)` 提亮**，不压暗——黑卡再压暗会和自身投影糊成一条，三层只能数出两层 |
| 前卡描边 | `inset 0 0 0 .5px rgba(255,255,255,.16)` — 硬卡的高光边 |
| 前卡投影 | `0 2px 7px rgba(29,28,26,.17)` |
| 前卡卡面 | 银行名 12.5pt/650 白 → 类型 9.5pt 76% 白 → 网络标 7pt/700 55% 白（右下）→ 负债卡加还款条（见第三节） |
| 数量角标 | 23pt 胶囊，`#1D1C1A` 底 + 白字 11pt/650，`right:9 bottom:6`（压在 k2 右下角，不贴容器边）；**账户数 = 1 时不显示** |

#### 2.3.1 为什么后层是账户彩色，不是白纸

**现行结论**：一摞彩卡才是真实钱包的样子。资产卡的品牌色本身就是信息，把后层刷白等于把"三张不同银行的卡"降级成"一张彩卡 + 两张纸垫"。

**被否决的白纸方案（2026-11-07 01:00 提出，11-08 否决，保留记录避免重走）**：当时为了"对齐首页日卡"，把后层改成纯白 + 1px 描边，理由是"一叠卡里能看见图案的永远是上面那张"。否决原因：首页日卡是内容卡（纸的隐喻成立），资产卡是实体卡（卡就是彩色的）；混用两套隐喻后，资产页读起来像"卡放在白纸上"而不是"一摞卡"。**代码里的 `stack` / `lum` 因此保留，不要删。**

**后续若再讨论**：先读 `history/设计方向-卡片堆叠-2026-11-06.md` 第四节，那里记了首轮彩色后层的三个毛病（同色系糊、暗橙变棕、3pt 白线读成描边），本次保留彩色后层是靠 `stack` 手工指定 + 亮度分档（.88/.76 / 深卡 1.22）解决的，不是靠"颜色随便挑"。

#### 2.3.2 为什么层厚必须 ≥ 16pt

v1.0 用 9pt（照搬首页日卡的 10pt）。但首页日卡是 358×722、圆角 24pt，10pt 层厚在 2.8% 的位置露出、面积很大；资产卡是 132×82、圆角 13pt，露 9pt 只有 11pt 高的条带，**整条都落在 13pt 圆角区内**，被两侧圆弧切掉，读成「卡片下垫了张纸」而不是「两张卡」。

16pt 刚好超过圆角半径，露出的是「一段直边 + 圆弧」，层才能数清。同理，旋转对小卡几乎无效：82 高的卡转 1° 角部只外扩 1.4pt（首页日卡 722 高转 1° 外扩 12.6pt），所以散叠感靠**下沉**而不是**旋转**来承载。

#### 2.3.3 与首页的异同

| | 首页日卡 | 资产卡堆（v1.1） |
|---|---|---|
| 后层材质 | 白纸 + 1px 描边 + 窄投影 | **账户彩色 + brightness 压暗**（唯一的实质不同） |
| 层厚 | 10pt × 3 层 | 16pt × 2 层（卡小，必须更厚） |
| 旋转 | ±1.0~1.3° | ±0.8~1.0°（小卡，转角幅度有限） |
| 前卡 | 白卡 | 彩色账户卡 |
| 层数规则 | min(天数, 7)，可见封顶 4 | min(账户数, 3) |

> 两处**不要求一致**：首页的产物是"纸"，资产页的产物是"卡"。这条差异是 11-08 定案，不要再"顺手对齐"。

## 三、还款进度（唯一的进度条位置）

**定义**：`本期已还 ÷ 本期应还`。仅负债卡有，储蓄卡不显示。

| 项 | 值 |
|---|---|
| 位置 | **收起态前卡卡内**，`margin-bottom:9px` 贴卡底但**不贴边** |
| 高度 | 2.5pt，圆角 2pt |
| 轨道 | `rgba(255,255,255,.32)` |
| 填充 | `rgba(255,255,255,.95)` 纯白 —— **不用红绿**（进度不是涨跌） |
| 数值 | 0% 时只有空轨道；100% 整条实白 |

**为什么必须离底 9pt**：贴底会和后层错位露出的 9pt 合并成一条横线，读成"只有两层"，堆叠感直接消失。

明细行的卡面上**没有**进度条（v7 明确删除）——收起态靠形态、详情页靠数字，中间那层不承担。

## 四、账户明细浮层（点开态）

### 4.1 形态：整屏磨砂，**不是 sheet**

| 项 | 值 | 为什么 |
|---|---|---|
| 容器 | `inset:0` 铺满，**无圆角、无把手、无上边距** | 圆角 + 把手 + 从底部升起 = sheet 的语法，一出现就被读成"半屏弹层" |
| 磨砂 | `rgba(247,245,241,.42)` + `backdrop-filter: blur(12px) saturate(1.16)` | 12px 是"色块可辨、字不可读"的分界；22px 时底下页面彻底消失，就失去了"没跳转"的证据 |
| 状态栏 | 在磨砂层**之上**重绘（9:41 + 电池），颜色与资产页同 | 这是"还在同一屏"的锚点 |
| 进入动效 | 磨砂 `.26s` 淡入 + 清单 `translateY(10px)→0` `.32s` `cubic-bezier(.32,.72,0,1)` | 只淡入 + 轻微上浮，**不要位移整屏** |
| 关闭按钮 | 30pt 圆形 ✕，`top:53 right:16`，`rgba(29,28,26,.07)` 底 | 没有把手，必须给明确出口 |
| 关闭方式 | ✕ / 点任意空白磨砂区 | 状态栏那条要 `pointer-events:none`，否则拦住点击 |
| 标题区 | **无**。不要标题、不要合计、不要逾期提醒 | 这些资产页上已有一份，重复即噪音 |

### 4.2 清单区

| 项 | 值 |
|---|---|
| 位置 | `top:92pt; bottom:0`（92 = 状态栏 52 + 40 留白） |
| 内距 | 左右 16pt，底 34pt |
| 底部渐隐 | `mask-image: linear-gradient(to bottom, #000 calc(100% - 30px), transparent)` |
| 滚动 | 隐藏滚动条；**一屏约 6.5 行** |

| 卡面圆角 | 15pt，`overflow:hidden` |

| 元素 | 规格 |

| 组 | 第一列 | 第二列 |
|---|---|---|
| 信用 | `欠款` / `−3,120.00` | `较上月` / `↘ 28.4%` |
| 储蓄 | `余额` / `1,204.30` | `较上月` / `↘ 6.2%` |

| 项 | 值 |
|---|---|
| 标签 | 10.5pt，`#9A968D` |
| 数值 | **16.5pt / 650**，`tabular-nums`，`letter-spacing:-.025em`，`margin-top:6px`，`nowrap` |
| 金额颜色 | **一律 `#1D1C1A`**。红色只给逾期白旗。红字压红卡会糊成一块 |

## 五、交互契约

| 动作 | 结果 |
|---|---|
| 点卡牌堆 | 打开**对应组**的浮层（信用堆 → 信用列表，储蓄堆 → 储蓄列表） |
| 点 ✕ | 关闭浮层，回到资产页（滚动位置不变） |
| 点浮层空白处 | 同上 |
| 点明细行 | 进账户详情页（**v1.0 未实现**，仅按下态 + 收尾文案暗示） |
| 打开浮层时底层页面 | 不重建、不位移、不改变导航栈 |

**进入终态需要两步**（先开堆、再点账户）——这是卡牌堆的固有代价，已接受，换来的是一屏干净。

## 六、SwiftUI 实现契约

### 6.1 浮层

```swift
ZStack {
  AssetsPage()                                  // 下层，始终渲染
  if let g = openGroup {
    Color.clear
      .background(.ultraThinMaterial)           // 必须挂在 Color.clear 的 background 上，才会糊到"身后"的兄弟视图
      .overlay(Color(hex: 0xF7F5F1).opacity(0.42))
      .ignoresSafeArea()
      .transition(.opacity)                     // 只淡入，不上移
      .overlay(alignment: .topTrailing) { closeButton }
  }
}
```

- **不能用 `.sheet`**，即使加了 `.presentationBackground(.ultraThinMaterial)` 也不行：detent、顶部圆角、拖动条、从底部位移，四样叠加就是"半屏弹窗"，与整屏朦胧互斥。
- `.ultraThinMaterial` 透明度过高，需配 `.overlay` 的 42% 米白压一层，否则文字和底下色块打架。
- **无障碍「降低透明度」开启时 material 会退化成实色**：回退顺序 `.regularMaterial` → `Color(hex: 0xF7F5F1).opacity(0.94)`。不能让灰字落在彩色卡面上。

### 6.2 卡堆

- `ZStack` + `.padding(.bottom, 16 * layerIndex)` + `.rotationEffect(.degrees([0, 0.8, -1.0][layerIndex]))`（`anchor: .bottom`）。
- **后层是账户彩色**（同账户 `c1/c2` 渐变 + `.brightness` 分档：浅卡 −0.10/−0.20，深卡 +0.10/+0.16），见 2.3 与 2.3.1。~~「后层是白卡」~~ 是 2026-11-07 的旧结论，11-08 已否决，不要再按白卡实现。
- 后层卡是**空视图**，不放任何文字——散叠缝隙里漏出后层内容会被读成排版错误。
- 层厚 16pt 与圆角 13pt 的关系是硬约束：层厚必须大于圆角，否则露出的条带会被圆弧吃掉（见 2.3.2）。

### 6.3 文字

- 所有数字 `.monospacedDigit()` + `.lineLimit(1)` + `.minimumScaleFactor(0.85)`。
- 96.5pt 列宽下 `−6,670.93` 与 `↘ 28.4%` 实测不换行。

## 七、数据契约

| 字段 | 类型 | 约束 |
|---|---|---|
| `n` / `m` | String | 账户名 / 类型说明。类型说明最多 1 行，超出用省略号 |
| `num` / `net` | String | 卡号掩码 / 网络标 |
| `c1` / `c2` | Hex | 卡面渐变起止色，深色到浅色（135°） |
| `debt` / `bal` | String | 已格式化金额（含 `−`），不在视图层算 |
| `delta` | String | `↗ 4.3%` / `↘ 28.4%`，已含箭头与百分号 |
| `dcls` | `up` / `down` | 只决定颜色，不决定箭头方向 |
| `u` | 0–100 | 还款进度百分比（仅负债） |
| `od` | String? | 逾期描述，非空即显示白旗 |

**口径**：`dcls` 对欠款是"变多/变少"，对余额是"涨/跌"；两者都遵循涨红跌绿，不需视图层区分。

### 8.1 详情页 v0.2 变更（2026-11-07，用户实机验收后）

两条来自实际看原型的否定意见，已落地：

| 项 | v0.1 | v0.2 | 为什么 |
|---|---|---|---|
| 走势图形态 | 阶梯折线（账单日上跳、还款日下跳） | **平滑曲线**（Catmull-Rom → 三次贝塞尔，系数 0.28） | 阶梯在小尺寸下读成「锯齿」而非「账单周期」，用户第一反应是图坏了 |
| 走势图取数 | `[账单日后, 还款日后]` 双值 | 只取**每月还款日之后的月余额**单值，12 个点等距 | 双值阶梯的横轴有两套时间含义，去掉阶梯后没有意义 |
| 走势图说明文案 | 「锯齿上跳是账单日、下跳是还款日」 | 「每月还款后的欠款余额」（储蓄为「每月末余额」） | 形态变了，解释必须跟着变；逾期账户另加一句「红点是 N 月账单漏还的开始」 |
| 详情页区块顺序 | 卡面 → 指标 → 走势 → 区间 → 对账 → 额度 → 分期 → 编辑 | 同上，但在「对账」之后插入**本期消费** | 「点进去要能看到这个账户花过什么」是一等功能，不能沉在最后 |
| 本期消费（信用） | 无 | 5–7 行：日期 / 商户+分类 / 金额；**各笔合计 = 本期应还** | 合计对不上账单，等于当场否定「余额对得上」这条底线 |
| 本期消费（储蓄） | 无 | 3–4 行，标题改「近期支出」，不给合计 | 储蓄的余额是存量，任何「合计」都会和余额打架 |
| 商户金额 | — | 每个商户带自己的区间（瑞幸 12–38、京东 59–420…） | 否则会造出「一杯瑞幸 96 块」，假数据一眼被看穿 |

**未闭合**：区间 pill（1周/1月/3月/今年/1年）目前只切换选中态，不换数据；「全部流水」按钮无去处~~（等流水页）~~——**已由 8.2 撤销，不再需要独立页**。

### 8.2 详情页 v0.3：流水分段与区块重排（2026-11-07，第二轮验收）

用户提问「全部流水的意义是？我已在账户详情页，不该能看到这个账户的全部流水吗」——结论：不做独立页，改页内分段。

| 项 | v0.2 | v0.3 | 为什么 |
|---|---|---|---|
| 流水入口 | 「本期消费」区 + 「全部流水 ›」按钮（跳新页） | 区头右侧 `本月 / 全部` 分段，同一位置换内容 | 已在账户上下文里，再跳一次只丢上下文；新页面没有任何独有内容 |
| 分段文案 | 本期 / 全部 | **本月 / 全部** | 首页只有 7 天，「本期」是账单期术语，与用户口语不符；本月是自然月 |
| 区块顺序 | 对账 → 本期消费 → 额度 → 分期 → 编辑 | 对账 → **额度 → 分期 → 流水** → 编辑 | 流水在「全部」下可达数百行，放中间会把额度和分期冲走；放最后则再长也不推走任何东西 |
| 合计校验 | 「各笔合计 = 本期应还 665.36 ✓」 | **撤销**。本月只给「合计 X」+「其中分期 X，新消费 Y」 | 本月 ≠ 账单期，本月消费大多还没出账，两个数本来就对不上。硬凑等于造假 |
| 还款记录 | 无 | **只在「全部」出现**：灰色 `+金额`，名称 = 资金来源账户（建行5044 / 支付宝），分类 = 还款 | 账户维度查账必须能看到「什么时候还过、还了多少」；本月按定义只有消费 |
| 全部列表 | 5–7 行一屏到底 | 月份分组（11 月 / 10 月 / 9 月）+ 每次 10 条 + 「显示更多」+ 「已到最早一笔」 | 花呗两年三四百条，必须分页；分组是查账时唯一能定位的锚点 |
| 储蓄账户 | 标题「近期支出」 | 统一「流水」，页脚「点『全部』看更早的 N 笔」 | 与信用账户共用一套控件，少一套分支逻辑 |
| 数据 | 7 行「合计 = 应还」 | 三个月倒序历史（手动 4 个账户 + seed 生成 13 个），信用账户每月补一条还款 | 「全部」要有东西可翻，而且还款间隔/金额必须看着像真的 |

**三个时间半径，互不重叠：**

| 半径 | 位置 | 回答什么 | 上限 |
|---|---|---|---|
| 7 天 | 首页卡片组 | 最近发生了什么 | 今天 + 往前 6 天，硬上限 |
| 本月 | 详情页 · 本月 | 这个账户这个月花了什么 | 自然月至今 |
| 全部 | 详情页 · 全部 | 从头到现在，含还款 | 无上限，10 条一批 |

三者分工清楚 → 首页不需要「更多」入口，账户详情也不需要跨账户搜索（那是全局流水 tab 的事）。

**未闭合**：① 区间 pill 仍只切换选中态 ② 「全部」暂无按类型筛（消费 / 还款 / 分期）③ 储蓄账户没有转入转出记录（PRD 未定义储蓄侧的 transfer 展示）④ **PRD 没有定义「按账户查流水」这个查询面**——欠款公式里有 `Σ消费(该账户付款)`，数据层能算，界面层一个字没写；接 Store 时要按 `accountId` 建索引。
