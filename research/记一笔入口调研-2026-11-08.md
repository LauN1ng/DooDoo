# 「记一笔」入口形态调研 · 2026-11-08

> 起因：`design/current/fab-options.html` 那四版（A 变小变轻 / B 文字胶囊 / C 金额入口 / D 卡内纸签）被否，判词是「**还是和首页的风格不符合**」。
> 这份文档回答两件事：① 之前为什么必然不符；② 从真实 App 里能找到哪些**不靠悬浮物体**的做法。
> 截图证据：`research/entry-patterns/`（均为 App Store 官方截图，2026-11-08 取）。

---

## 零、结论先行

**前四版失败在同一个地方：它们都是「物体」，而首页是「纸」。**

首页的语言是：暖白底、白纸卡、1px 细线、极轻投影、墨色只在很小的面积上出现。纸的世界里没有悬浮的实体——只有**印刷的字、页签、行、裁切线**。所以一个 44~127pt 的实心块，无论圆的还是长的，都只能是「贴上去的一张黑胶带」。

出路不是把按钮再改小，而是**换层级**：让入口成为页面结构的一部分（一行、一条页脚、一枚页签、或干脆没有按钮）。

---

## 一、七张参考图与它们各自能抄的东西

| # | 应用 | 截图 | 入口形态 | 抄什么 / 不抄什么 |
|---|---|---|---|---|
| 1 | 钱迹 | `qianji-3.png` | 记账页**没有返回按钮式入口**，打开就是「支出/收入/转账 + 分类九宫格 + 键盘」，金额行贴在键盘上方 | 抄：**入口可以是一次跳转的结果，不必是一个常驻物体**。钱迹甚至做了「秒开模式」——桌面点开直接进这一屏 |
| 2 | 钱迹 | `qianji-1.png` | 首页是仪表盘（月结余 / 预算 / 近七日 / 报销），**没有 FAB** | 抄：首屏留给信息，不给按钮。DooDoo 反过来——首屏已经全是流水，更不该再塞重物 |
| 3 | MOZE | `moze-1.png` | **「＋」在底部 tab 栏正中间**，是五个槽之一，比别的槽大一圈、带细环 | 抄：**把动作放进「家具」里**，与其它槽同一套材质，不悬浮在内容之上。不抄：DooDoo 底部 tab 已取消，不能为它复活一条底栏 |
| 4 | MOZE | `moze-3.png` | 资产页右上角，**分类图标 + ＋ 并排**，都是 24pt 线图标，没有任何容器 | 抄：最安静的做法——把 ＋ 降级成「页头的一个图标」，与其它图标同级。这条与已定案的顶部 tab 天然兼容 |
| 5 | 一木记账 | `yimu-1.png` | 汇总卡下面一条**整宽「添加一条新记账」**，位于页面流内、列表之上 | 抄：**入口是一条「条」而不是一个「块」**，占满宽度后它读成结构，不读成按钮。不抄：实心绿太重，DooDoo 要用纸面/描边 |
| 6 | Things 3 | `things-1.png` | 右下角一枚**小圆 ＋**（约 40pt），贴角、半只压在内容上 | 抄：如果非要悬浮，**小 + 贴角**是唯一不太碍眼的比例（现在 DooDoo 的 52pt 纯黑球太重）。不抄：彩色实心圆的语言与纸无关 |
| 7 | Things 3 | `things-2.png` | 同上，＋ 在长列表右下角，永远浮在同一位置 | 抄：悬浮的唯一好处是**永远在手边**——这条要保留给某一版备选 |

**一句话总结参考**：安静的应用把「添加」做成了**结构**（一行 / 一条 / 一个图标），只有强调效率的应用才把它做成**物体**（悬浮球），而做物体的往往靠品牌色和尺寸控制重量。DooDoo 没有品牌色可用，所以只能走「结构」这条路。

## 二、四个新方向

> 共同前提：**都不再是悬浮块**。四版都能满足「不压层厚带（38→8 每层 10pt）」与「与顶部 tab 同一套材质」。

### A · 页头 ＋（与 tab 同一行）

| 项 | 值 |
|---|---|
| 形态 | tab 胶囊右侧 8pt 处一枚 **34×34 圆角 17 的浅槽 + 墨色 plus 17pt**，无描边、无投影，槽色同 `#EBE7E0` |
| 位置 | 页头 `.hd`（top 52 / 高 34）内，右内距 20 |
| 参考 | MOZE 资产页（`moze-3.png`）把 ＋ 与其它图标并列 |
| 好处 | 不占底部、不遮卡片、与刚定案的 T1 完全同族；底部彻底留空，层厚带完整 |
| 代价 | ① 记账是每天 3~5 次的高频动作，放屏幕顶对单手不友好；② 与 tab 同处一行，容易误触；③ 顶部一行变成「导航 + 动作」两种语义 |
| 尺寸冲突 | 加上后右端占 112 + 8 + 34 = 154，字标↔控件从 157.9 降到约 116，仍 ≥60，可用 |

### B · 记账行（今天卡的最后一行）

| 项 | 值 |
|---|---|
| 形态 | 卡片底部内侧**固定一行 56pt**（不随 rows 滚动）：左侧 42×42 **虚线空槽**（`inset 0 0 0 1px dashed rgba(29,28,26,.18)`，圆角 13），右接「记一笔」13pt 墨 62% |
| 位置 | `.rows` 之外、卡片 padding 内；始终可见 |
| 参考 | 一木的整宽条（`yimu-1.png`）+ 账本的空行隐喻 |
| 好处 | **最强的隐喻**：记账就是在这张纸上加一行。与流水行同节奏（42 图标槽 / 14pt 字号），读成内容而不是按钮；不悬浮、不遮层厚带；每张日卡都有，翻到历史日自动变成「给 X 月 X 日补记」 |
| 代价 | 占 56pt 卡内高度（当前卡 682，剩 626）；虚线槽是新的视觉元素（但只有一条，且用虚线而非墨色） |
| 内边距 | `padding-bottom` 从 70 改为 **16**（该行自己撑起底部空间），rows 的可视高度不变 |

### C · 页脚墨线栏

| 项 | 值 |
|---|---|
| 形态 | 屏幕底部一条 **44pt、无背景、无阴影**的栏，只有一条 1px `#EAE7E0` 上边线；左「今天 3 笔 · ¥165.00」11pt 灰，右「＋ 记一笔」12.5pt 墨 |
| 位置 | 屏底 0~44；卡堆底距从 8 抬到 **52**，层厚带（52→22）完整在栏上方 |
| 参考 | Things 的底部条 + 一木的整宽条，但去掉容器 |
| 好处 | 永远可见；重量极轻（无容器无投影，只有一条线）；信息顺带（今天几笔） |
| 代价 | 等于重新引入「底栏」，与「底部只留记一笔」的决定表面冲突（但它是页脚，不是控件组）；卡片矮 44pt |

### D · 卡沿纸签

| 项 | 值 |
|---|---|
| 形态 | 卡片**右边缘伸出一枚 28×64 纸签**，与卡同材质（白 + `inset 0 0 0 1px rgba(29,28,26,.12)` + 右侧投影），竖向「记一笔」9.5pt 或 17pt plus |
| 位置 | 卡片右侧 −10pt，纵向居卡片下三分之一 |
| 参考 | 实体账本/文件的索引贴 |
| 好处 | 最「纸」的一版；不遮内容、不占底部、不抢顶部 |
| 代价 | 贴屏幕右缘，44pt 圆角处可能被切；命中区窄（28×64），单手可及但误触边缘会触发系统返回手势 |

### E · 备选：没有按钮

| 项 | 值 |
|---|---|
| 形态 | ① 长按今天这张卡 300ms → 键盘上滑；② 或从卡堆顶部下拉 → 出键盘 |
| 参考 | 钱迹的秒开模式（`qianji-3.png`）：记账页本身不需要入口 |
| 好处 | 首页零控件，最干净 |
| 代价 | 可发现性差（新用户永远找不到）；长按与现有的横滑翻卡、纵向滚动叠在一起，手势仲裁变复杂 |

## 三、我的建议

**主推 B（记账行）**：它是唯一「把动作变成内容」的方案，也是唯一每张日卡都自带入口的方案——翻到 11-03 时那行自动变成「给 11-03 补记」，正好补上 D 版没解决的日期语义。

**如果还想要一个永远可见的兜底**：配 C（页脚墨线栏），而不是 A。理由：A 把动作塞进导航行，语义混杂且够不到；C 与记账这件事的「每天一条」节奏更配。

**不建议**继续在「悬浮块」里调参数（尺寸、阴影、圆角）。四版已经证明这条路在纸的语言里没有解。
