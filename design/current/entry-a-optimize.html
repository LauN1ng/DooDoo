具体减了什么

#改动腾出为什么不算「藏字段」
1删掉「记一笔 + 今天」标题行，日期并入类型行右端≈40pt日期仍可见可点，只是不再单独占一行
2灰底四类型 segmented → 无容器文字 tab（选中加下划线）≈12pt四个类型一个不少，仍可直接点
33 条独立 label 行 → 行首 38pt 窄标签，与控件同一行≈60pt「分类 / 账户 / 值不值」语义全保留
4药丸去边框、分类方块 46→42、评分胶囊→34pt 圆点≈8pt控件尺寸变小，数量与可选值不变
5备注 / 日期 / 分期 三个带框 chip → 一行纯文字 + 圆点分隔≈14pt三项仍可点，分期内联开关还在
6键盘键高 46→44、gap 6→5≈11pt16 个键一个不少
7金额 50→62px，上下 padding 12→16/18−22pt把省下的空间花在视觉主角上
净效果≈120pt控件总数不变，标签行数 −3，带框容器 −5
刻意没动的东西 纸卡层叠几何（top 96 / 后层露 16pt / 26px 圆角）、首页与资产页视觉 token（暖白 #F7F5F1、白卡、极轻双层阴影、Emoji 浅底容器、红绿克制色、黑色动作键）、四类型切换后的字段差异（还款 = 账单期 + 不计支出；转账 = 双金额 + 手续费）、评分四档夯/飘/拉/NPC 可跳过、PRD 字段全集。
优化只作用于 A，B / C / D 三版未改。
验收与仍有代价 浏览器逐版截图 + 计算样式核对（完成键 rgb(29,28,26)、选中药丸同为墨黑，没被覆盖成白底）+ 交互脚本全通过：还款/转账字段切换、分类点选、键盘输入、保存 toast 都正常。
两个仍在的代价：① 行首 38pt 标签占了宽度，分类横滑一屏可见从 6–7 个降到 5 个；② 键盘 4×4 在 390pt 宽里仍偏小，这是「一屏录完」的固有成本。
如果还嫌挤，下一步只能动控件数量（把分类/账户/评分折叠成一行摘要、点击展开）——但那就接近 B 了，需要你先拍板。
