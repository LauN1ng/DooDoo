记一笔 · 四版对比

四版共用同一份卡堆、同一个顶部 tab、同一套 token，只换记一笔这一个控件——否则差异会来自页面而不是控件。每版都按自己的控件高度重算了卡内下内边距，保证流水行与控件之间留 12pt。

先说三条硬约束（四版都必须满足）

① 不许压层厚带：卡堆底部三层各露 10pt，那是「有几天」的唯一证据，控件只能停在最上层卡面里或卡面之外，不能穿过去。

② 卡内下内边距跟着控件走：padding-bottom = 控件顶到屏幕底 − 卡下沿到屏幕底 + 12。当前卡下沿 38pt，A 版控件顶 98pt ⇒ 72pt，以此类推。这个数不能拍脑袋写死，历史已经踩过一次（底部 tab 换方案后没重测）。

③ 首页主数字是卡头那个「支出 −¥165.00」。任何把同一个金额再显示一遍的方案（C）都要解释为什么值得重复。

A 变小变轻一枚安静的黑点，随手可点不抢存在感弱 → 单手拇指区域仍在右下没问题，但「记一笔」这句话消失了，新用户要靠形状猜不遮
B 文字胶囊一个明确的主按钮不抢横向变长（96pt），压到卡面右下角更多面积；文字在小屏上会被截断的风险低但要留 18pt 内距不遮
C 金额入口一个「今日花了多少 + 记一笔」的复合按钮重复：卡头已有 −¥165.00同一数字出现两次，且按钮比卡头更抢眼，等于把主数字的位置搬到角落；一旦跨月/跨天口径不一致会直接矛盾不遮
D 与卡堆融合这张纸的「下一行」不抢只在「今天」这张卡上成立；翻到历史日时按钮语义变成「给那天补记」，需要额外文案；且它随卡堆一起翻走，不再是全局入口不遮

四版共同的结论

  • 底部只剩一个控件，所以它必须承担「记一笔」的全部可发现性。上一轮底部有两个黑物（tab 胶囊 + FAB）互相呼应；现在 tab 上了顶部，底部独苗，A 版最轻但最容易被忽略。
  • D 的语义最好、可用性最差。「记一笔 = 在这张纸上加一行」是这个产品最好的隐喻，但它只对「今天」这张卡成立；翻回 11-03 时按下去应该是「给 11-03 补记」——这需要额外文案，否则会误记到错误日期。
  • C 是唯一会伤到信息架构的方案。卡头的 −¥165.00 是首页第一眼要读的数字，角落里再放一个同值胶囊，用户会开始怀疑哪个是「真的」。
